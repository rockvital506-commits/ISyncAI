# И‑026 · Адаптер Kilo: замысел до прогона

18 ноября 2026. Правило тождества не меняется (0.1.5 принят в И‑025). Предмет итерации — **среда**:
у Kilo Code свой список источников инструкций, свой порядок старшинства и свои ограничения. Задача
адаптера — не «положить файл», а честно знать эту среду и не создавать второй реестр.

## Что известно про Kilo Code (сверено с документацией 18.11.2026)

| Свойство | Факт | Источник |
|---|---|---|
| Файл входа | `AGENTS.md` в корне проекта; `AGENT.md` — запасное имя. Регистр обязателен | [kilo.ai/docs](https://kilo.ai/docs/customize/agents-md) |
| Старшинство источников | 1) промпт агента в конфиге, 2) ключ `instructions` в проектом `kilo.jsonc`, 3) корневой `AGENTS.md`, 4) глобальный `instructions`; навыки — по требованию | [kilo.ai/docs](https://kilo.ai/docs/customize/agents-md) |
| Старые каталоги правил | `.kilo/rules/` — текущий, `.kilocode/rules/` — совместимость, `.kilocoderules` — наследие | [deepwiki](https://deepwiki.com/Kilo-Org/kilocode/8.3-agent-rules-and-workflows) |
| Подкаталоги | `AGENTS.md` в подкаталогах подгружается по факту чтения файлов оттуда | [kilo.ai/docs](https://kilo.ai/docs/customize/agents-md) |
| Защита файла | `AGENTS.md` защищён от записи: агент не меняет его без явного согласия человека | [kilo.ai/docs](https://kilo.ai/docs/customize/agents-md) |
| Когда применяется | правки вступают в силу в новых задачах; иногда нужна перезагрузка | [kilo.ai/docs](https://kilo.ai/docs/customize/agents-md) |
| `.clinerules/` | в документированных источниках Kilo его нет | [memorylake](https://www.memorylake.ai/en/blogs/migrate-cline-to-kilo-code) |

Главное следствие для комплекта: **вход комплекта уже совпадает с входом Kilo** — `ENTRY = 'AGENTS.md'`.
Но он стоит на третьем месте, а не на первом: два источника старше него, и оба — конфигурация. Значит
адаптер обязан (а) знать и показывать эти источники, (б) не трогать их, (в) не выдавать присутствие
файла за проверенное обнаружение.

## Что делает адаптер (и чего не делает)

| Делает | Не делает |
|---|---|
| выдаёт карточку среды `adapter kilo`: вход, старшинство, список источников, что не проверено | не пишет в `.kilo/`, `.kilocode/`, `kilo.jsonc`, `AGENTS.md` без команды `connect` |
| видит `.kilo/kilo.jsonc`, `.kilo/rules`, `.kilocode/rules`, `.kilocoderules`, `AGENT.md` | не читает содержимое этих файлов |
| требует подтверждения списка источников до создания входа | не переносит правила в формат Kilo и не создаёт второй реестр |
| показывает, что старшинство 3 из 4 — данные, а не проверка | не заявляет обнаружение: `discovery_proven: false` |

## Ожидания, зафиксированные до сборки выпуска

| Что | Ожидание |
|---|---|
| Испытания комплекта | 42 pass / 0 fail / 3 not run, обе линии (было 38) |
| `adapter kilo` | карточка без записи в проект; неизвестное имя → отказ `adapter_unknown` |
| Проект с `.kilo/kilo.jsonc` | `connect` без `ack_existing` → отказ `existing_sources` с точным списком |
| С тем же проектом после подтверждения | вход создан, файлы Kilo байт в байт не изменены |
| `AGENT.md` в корне | тоже требует подтверждения (запасное имя входа Kilo) |
| Правило тождества | не менялось: корпус 24 склейки (12 + 12 объявленных), журналы 3 из 3, 0 ложных из 40 |
| Данные 0.1.5 | читаются 0.1.6, чтением не переписываются |

## Что будет означать провал

- карточка адаптера пишет в проект или читает содержимое чужих источников;
- `connect` проходит без подтверждения при наличии источника Kilo;
- файлы `.kilo/**` меняются хотя бы на байт;
- правило тождества поехало: корпус или журналы дают другие числа;
- обнаружение в живом Kilo заявлено как проверенное.

## Границы

Живой Kilo Code здесь не запускается: плагин, модель и загрузка правил в редакторе — предмет уровней
достоверности (И‑030…И‑032) и живых моделей (И‑045). Поэтому `discovery_proven: false` — это не
оговорка, а поле ответа. Windows, права и журналы заказчика — по-прежнему `not run`.
