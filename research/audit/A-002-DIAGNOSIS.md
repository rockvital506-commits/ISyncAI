# A-002 · Почему тесты 105/107/108/109 не проходят — и что значит «починить»

**Дата:** 2026-11-24 · **База:** `f330f6a` · **Метод:** bisect по истории `kit/base`, а не чтение кода

## 1. Главный факт: они не были сломаны

Каждый из четырёх тестов **проходил на своём коммите**. Проверено прогоном в отдельном дереве
(`git archive <commit>` + `python3 -I`), без правок:

| Тест | Проходил на | Перестал проходить на | Что изменила та итерация |
|---|---|---|---|
| `105/test_layout.py` | `8e03563` = И‑105 | `23b320b` = **И‑106** | файл L1 получил обёртку `profile_format`/`journal` |
|   |   | `39c83e3` = **И‑107** | код ошибки `invalid_entry` → `parent` (A4) |
| `107/test_policy.py` | `39c83e3` = И‑107 | `7ba1c7e` = **И‑110** | 14 ячеек матрицы `planned` → `available` |
| `108/test_cards.py` | `1e6add9` = И‑108 | `c5fec24` = **И‑111** | добавлен вопрос `persistence` |
| `109/test_plan.py` | `57d7021` = И‑109 | `7ba1c7e` = **И‑110** | `create` расширен с `rule` на все 5 видов; L2 через карточку; исход `listed` |

**Вывод:** это не регрессии. Это **устаревшие снимки ожиданий**. Каждое изменившееся поведение
задокументировано в своей итерации — см. §3.

## 4. Препятствие: тесты входят в запечатанные архивы

`test_layout.py`, `test_policy.py`, `test_cards.py`, `test_plan.py` — **члены 20-файловых печатей**
своих итераций (проверено: файл в ZIP байт-в-байт равен живому). `run.py` каждой итерации запускает
**живой** файл по пути `research/NNN/test_*.py`.

Значит правка на месте означает:

1. Печать на диске останется валидной (SEAL хеширует ZIP, а не живой файл) — **но**;
2. живой тест перестанет быть равен копии в архиве;
3. вопрос «чем на самом деле проверяли И‑105» станет недоказуемым из рабочего дерева.

За всю историю **ни один** тест прошлой итерации не правился: у всех ровно один коммит.
Это устойчивая конвенция, и ломать её молча нельзя.

## 5. Что это значит для «шага 0» из моего же разбора

Я предложил «починить 105/107/108/109». Формулировка была **неверной**: чинить нечего —
код здоров, а тесты являются историческими актами приёмки, а не живым набором регрессии.

Правильная задача: **сделать текущее поведение проверяемым**, не переписывая историю.
Прецедент в репозитории уже есть — `research/audit/state_audit.py` (A‑001): живой аудит,
который прогоняет выпуск и сверяет с эталоном, не входя в запечатанный состав итерации.
