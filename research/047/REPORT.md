# И‑047 · Контур машины состояний — отчёт

18 ноября 2026. Выпуск **0.1.27**. Итерация закрывает аудит A‑001: машина состояний теперь спрашивает
состояние на входе, а чтения называют причину, а не только число.

## Аудит, из которого выросла итерация

| Что проверено | Итог |
|---|---|
| матрица переходов, 4 состояния × 4 цели × (контракт, правило) | 32 пары, `matrix_gaps: []` |
| чтения под `suspended`-контрактом | `list 0`, `metrics.hidden 1`, `noise 1` |
| чтения под `revoked`-контрактом | `hidden 1`, `revoked 1` |
| проект `retired` | `list 0`, `hidden 1`, `health retired` |
| инварианты счёта (5) | все `true` |
| вход: `create`/`state` | 3 дыры — A1, A2, A3 |
| `due` без `state`, `hidden` без причины, `hidden` при `target` | A4, A5, A8 |

Чистым оказалось то, что обычно ломается: `purge` доступен только из `revoked` и только с
`allow_delete`; `edit` и `review` отменённой записи отклоняются; `revoked` не попадает в `due`;
`retired` считается отдельно. Найденное — не в переходах, а на входе и в словаре чтений.

## Что появилось

| Правило | Ответ |
|---|---|
| мёртвая ветка | `create` под `revoked`-контрактом — отказ `parent` с `{contract, state}` |
| действующая запись | `active` под `draft`/`suspended`/`revoked` — отказ `state` с `{contract, parent_state}` |
| отложенная запись | `draft` под неактивным контрактом создаётся: черновик ждёт возвращения контракта |
| `due` | каждая строка называет `state` |
| `hidden` | `by_reason`: `parent_draft`, `parent_suspended`, `parent_revoked`, `retired` |
| `hidden` и `target` | вне области — не «скрыто»; `active` сужается, как прежде |
| схема | не ужесточена: старые записи читаются |
