# Agent Contract Kit • 0.1.0

Самостоятельный офлайн-комплект для контрактов между владельцем, проектом и AI-агентами. В чистом выпуске **0 контрактов, 0 пользовательских правил, 0 настроек и 0 пользовательских протоколов**. Отсутствуют профили, входы, установленные интеграции и выдуманные успешные проверки. Документ `PROTOCOL.md` описывает механику программы, а не навязывает пользовательскую политику.

## Состав поставки

| Путь | Что это |
|---|---|
| `kit/base/START.md`, `kit/base/PROTOCOL.md` | Короткий вход и руководство по диалоговым операциям, версиям, восстановлению и ограничениям. |
| `kit/base/schema.json`, `rules.json`, `entry.txt`, `manifest.json` | Описание формата №1, пустой канонический реестр, неактивный шаблон общего входа, состав и происхождение базы. |
| `kit/tools/contract.py` | Исполняемый механизм. Локальный JSON-интерфейс для человека, агента или автоматизации. Только стандартная библиотека Python; не служба и не плагин. |
| `kit/tests/test_contract.py` | Автоматические сценарии с синтетическими данными, каждый строит собственные A/Б/контроль. Никакого доступа к реальным агентам. |
| `releases/0.1.0/`, `releases/0.1.4/` | Неизменённый предок и текущие шесть файлов данных. В проект устанавливается только выбранная одобренная версия. |
| `reports/CHECKS.json`, `reports/PIPELINE.json` | Результаты именно этой сборки и отдельной сквозной имитации. В новый проект эти отчёты не переносятся. |
| `SHA256SUMS` | Отпечатки файлов архива, кроме самой ведомости. Ведомость не является электронной подписью. |

Логическая цель размещения в Windows: `%USERPROFILE%\AgentContractLab`. Архив содержит один такой корень. Привязок к абсолютным путям компьютера разработчика или к ISyncAI в переносимой базе нет. Для работы с данными не нужен Git, переименование веток или подключение к серверу. Для утилиты и тестов предназначен Python 3.11+; это не утверждение о его наличии в Windows пользователя.

## Как работает система

Агент понимает фразу в диалоге и переводит её в одну из ограниченных операций. Сама программа не вызывает модель и не пытается угадывать намерение по ключевым словам. `session` для разового указания, предложения или гипотезы ничего не сохраняет. Постоянная договорённость проходит `plan` → показ точной разницы → согласие на этот план → `apply`. В тестовых каталогах роль владельца выполняет сценарий. Для реальных изменений билет — проверка актуальности, не способ заменить согласие или разрешения ОС.

Сначала `install` устанавливает **данные** в отдельный проект, не создавая агентский вход. Общий для пилота `AGENTS.md` появляется только после одобренного `connect`. `inventory` показывает существование известных локальных точек инструкций, не открывая их содержимое. При их наличии запрос подключения возвращает пути: для явного сосуществования поле `ack_existing` должно содержать эти пути в указанном порядке. Изменение метаданных до применения аннулирует билет. Уже занятый чужой `AGENTS.md` не присваивается даже с этим полем. Полезный запасной вариант — чтение `START.md` по запросу. Свободный выбор настоящей среды и разрешения инструментов остаются вне комплекта.

Внутри проекта источник локального состояния — `.agent-contract/project/state.json`. Одно изменение записи и решение о нём сохраняются вместе. Создание нескольких независимых контрактов, области, переходы, отзыв и отдельное удаление — реальные операции, а не только договорённости в Markdown. Права/область одного контракта не перетекают автоматически в другой. Ключ и значение позволяют проверять формализованную часть противоречий, а не весь естественный язык.

Обновление сравнивает сохранённый выпуск, текущую базу и одобренную новую версию. При изменениях одного ID с обеих сторон требуется выбор. При отсутствии исходной версии запись останавливается. `updates` показывает локальные выпуски и признак более новой версии, если указан установленный проект; кандидат не считается доверенным только потому, что найден на диске. Миграция имеет проверяемое преобразование 0 → 1; неизвестный формат не переписывается. `retire` отключает вклад контракта, но не удаляет его историю.

Фактический интерфейс, поля всех запросов, различия между `restore` и `undo` — в `kit/base/PROTOCOL.md`. Примеры рабочих вызовов для автоматизации содержатся также в тестах. Команды не исполняются при чтении этого документа или распаковке архива.

Фактический прогон: Linux / Python 3.11.2. Отчёт содержит 35 `pass`, 0 `fail`, 3 `not run`: Windows junction и два настоящих сеанса расширений. Проверялись пустота базы, циклы записей и контрактов, перенос, конфликты при слиянии, миграция, защита от устаревшего плана, два процесса записи, изменение постороннего файла, реальная остановка дочернего процесса после второй замены и побайтовое восстановление. В независимой имитации 36 отдельных запусков CLI; контрольное дерево C без контракта, в Б нет локальной метки А. Имитация не измеряет качество моделей.

По данным владельца целевая среда: Windows 11, VS Code 1.146.0, расширения Copilot и Kilo Code. Их версии, настройки и фактическое чтение в данной установке не проверены. Наличие `AGENTS.md` — только наличие файла; оно не доказывает обнаружение, загрузку, выполнение или повторяемость. Основание для выбора входа: справочник Microsoft `microsoft/vscode-docs`, ревизия `449410e3df07db8a6a017a1a13eea9638aea755c`, `docs/agents/reference/custom-instructions-reference.md`; справочник Kilo `Kilo-Org/kilocode`, ревизия `46e4dd47e524d79ddd40c57ad633b13fc6b6bcec`, `packages/kilo-docs/pages/customize/agents-md.md`. В работе утилиты обращений к этим источникам нет.

Структурные тесты повторяемы из самого комплекта: `python -I -B kit/tests/test_contract.py`. Раннер всегда создаёт новый каталог `runs/`, не очищает предыдущие и не использует реальные проекты как полигон. Полный регламент не требует от владельца проведения ручных тестов. Результаты действительны только для проверенной среды.

## Восстановленная линия

Выпуски `0.1.1`–`0.1.3` и их архивы утрачены: каталог `dist/` не попадает в снимки рабочего пространства и не хранится в git. Эта линия выведена заново от `0.1.0` и содержит оба правила: побайтный повтор (из 0.1.3) и смысловой повтор (из 0.1.4). Исторических снимков `releases/0.1.1`–`releases/0.1.3` в поставке нет, поэтому переход с этих версий невозможен; переход с `0.1.0` проверен сквозной имитацией. Номер `0.1.4` сохранён, потому что правило и его приёмка те же; байты архивов отличаются от утраченных.
