# И‑052 · Пригодность к применению — дополнения и их разбор

18 ноября 2026. База: **AgentContractKit 0.1.31**. Текущая фаза — не новые правила и не ядро ISAI, а
**пригодность системы к применению** в вашем сценарии:

> распаковать архив в корень репозитория → выдать агенту права на папку → отправить инициализирующий промпт.

Ваши дополнения к этой фазе: (1) промпты калибровки и эталонные ответы, (2) эталоны недоступны до ответа,
(3) README как максимально подробная памятка для двух ролей. Ниже — критический разбор и принятая версия.

## 2. Критический разбор

### 2.1. Промпты калибровки

**Польза.** Единственный способ проверить работоспособность *после переноса* — прогнать известный сценарий и
сверить ответ с известным ожиданием. Это ровно то, чего не хватает сейчас: 93 испытания доказывают, что
комплект собран правильно, но не доказывают, что **распакованный архив на вашей машине ведёт себя так же**.

**Риски.**

- **Р1. «Самоисправление» может стать тихой правкой правил.** Агент, найдя расхождение, поправит правило или
  базу, и отчёт будет зелёным. Недопустимо: база — данные выпуска, правила — текст владельца.
  *Решение:* самоисправление — **закрытый список** восстановительных действий, только через `plan`/`apply`,
  только внутри `.agent-contract/`; всё смысловое — в раздел «нужно от пользователя».
- **Р2. Расхождение из-за среды, а не из-за системы.** Другой `os`, чужая локаль, чужой `AGENTS.md` —
  калибровка «провалится» честно, но это не дефект. *Решение:* эталон задаётся **по полям**, и поля делятся
  на «инвариантные» (не зависят от среды) и «средовые» (сверяются как «допустимо»). Вердикт различает
  `mismatch_data` и `environment`.
- **Р3. Проза нестабильна.** Одинаково правильные ответы формулируются по-разному. *Решение:* вердикт
  считается **только по каноническому JSON**; проза — для человека и в вердикт не входит.
- **Р4. Бесконечный цикл.** «Прогнать ещё раз?» без правила превращается в ритуал. *Решение:* повтор
  предлагается только если `match == false` **и** причина в данных, и максимум один повтор без изменений.

**Вердикт: принять с изменениями Р1–Р4.**

### 2.2. Закрытые эталоны

**Польза.** Без этого калибровка — самообман: агент видит ответ и «воспроизводит» его.

**Риски.**

- **Р5. Технически недоступность не гарантируется.** Если эталон лежит файлом, его можно прочитать —
  в проектных инструкциях нет технической защиты от чтения. Обещать «недоступен» нельзя (§4 п. 8).
  *Решение — два уровня:*
  - в поставке лежат **только дайджесты** эталонов (`sha256` значений по полям) — **значений нет**, поэтому
    подгонка невозможна в принципе: нельзя скопировать то, чего нет;
  - **прозаический эталон** («как должен выглядеть ответ и почему») — в **отдельном архиве**, который
    открывают после отправки ответа. Порядок — часть методики; кто открыл раньше, обязан это сказать.
- **Р6. Дайджест не объясняет, что не так.** Хеш говорит «не совпало», но не «почему».
  *Решение:* дайджест **по каждому полю** — расхождение локализуется до имени поля; проза из отдельного
  архива объясняет смысл.

**Вердикт: принять с изменениями Р5–Р6 (дайджесты в поставке, проза отдельным архивом).**

### 2.3. Подробный README

**Польза.** Вектор смысла: пользователь освежает память, модель получает ориентир при отклонении. Это дешевле,
чем перечитывать `PROTOCOL.md` на 60 КБ.

**Риски.**

- **Р7. README начинает жить своей жизнью.** Второй источник истины → расхождение с `START.md`/`PROTOCOL.md`.
  *Решение:* README **не переписывает** правила, а ссылается; каждое нормативное утверждение имеет якорь
  (`[START §7]`, `[PROTOCOL: чужая файловая система]`), и тест ловит утверждения без якоря и якоря в никуда.
- **Р8. Простыня, которую модель не читает.** «Максимально подробно» ≠ «максимально длинно».
  *Решение:* лимит 24 КБ на README, оглавление на 3 входа (пользователь / агент / проверяющий), детали —
  ссылками. Полнота проверяется покрытием смыслов, а не объёмом.
- **Р9. README обещает больше, чем есть.** *Решение:* раздел «Чего нет» обязателен и сверяется с реальным
  списком `not run` из приёмки.

**Вердикт: принять с изменениями Р7–Р9.**

## 3. Принятая версия (что именно внедряем)

### 3.1. Новые артефакты в поставке

| Файл | Линия | Назначение |
|---|---|---|
| `kit/base/calibration.json` | base + edition | промпты калибровки: id, шаги, схема ответа, **дайджесты эталона по полям** |
| `docs/КАЛИБРОВКА.md` | base + edition | текст промптов: что запустить, что считать ответом, что запрещено |
| `docs/INIT-PROMPT.md` | base + edition | инициализирующий промпт (§13) — то, что вы вставляете новому агенту |
| `README.md` (переписан) | base + edition | вектор смысла: пользователь / агент / проверяющий / границы / «чего нет» |
| `docs/ЭТАЛОНЫ-ПОСЛЕ.md` | **отдельный архив** | прозаические эталоны; открываются после отправки ответа |
| команда `calibrate` | инструмент | список промптов, приём ответа, сравнение, отчёт, безопасные починки |
| команда `access` | инструмент | измеренные права на 9 путей записи |

### 3.2. Форма ответа на промпт калибровки (единая)

```json
{
  "prompt": "K1",
  "system_version": "0.1.36",
  "schema_version": 1,
  "environment": {"os": "posix", "case_insensitive": false},
  "facts": {"status.health": "valid", "rights.write_paths": 9, "model.live": false},
  "not_run": [{"what": "живая среда VS Code", "why": "расширения не запускаются"}],
  "manual": ["вставить строку из brief в свой AGENTS.md"],
  "verdict_self": "checkable"
}
```

- Вердикт считается **только** по `facts`.
- Канонизация: ключи по возрастанию, UTF-8, без пробелов, значения — только строки/числа/булевы/`null`.
- `not_run` обязателен: пустой список означает «всё проверено», и это отдельно сверяется с эталоном.

### 3.3. Промпты (минимальный набор, каждый — отдельный вход)

| id | Что проверяет | Ключевые поля `facts` |
|---|---|---|
| **K1 «база»** | система на месте и читается | `status.health`, `entry_mode`, `list.active`, `rights.write_paths`, `system.os`, `model.live`, `repeat.identical` |
| **K2 «правило»** | машина состояний: создание → приостановка → отмена | `list.active`, `metrics.active.count`, `due.count`, `removed.count`, `history.decisions` |
| **K3 «сбой»** | частичный сбой виден и восстанавливается | `pending.count`, `pending_detail.files`, `restore.outcome`, `status.health` |
| **K4 «перенос»** | базовая часть переносится без проектных данных | `transfer.files`, `transfer.excluded`, `install.outcome`, `digests.equal` |

Четыре — потому что у каждого свой код отказа и свои условия приёмки; склеивать нельзя (правило единицы счёта
линии). Остальные сценарии (обновление, миграция, конфликт правил) остаются в `PROTOCOL.md` и в испытаниях.

### 3.4. Закрытые эталоны — как это выглядит

```json
{"prompt": "K1", "schema_version": 1, "system_version": "0.1.36",
 "facts": {"status.health": "<sha256(значения)>", "rights.write_paths": "<sha256>", "...": "..."},
 "facts_digest": "<sha256(канонический facts)>",
 "not_run_expected": ["живая среда VS Code", "поведение моделей"],
 "note": "Значений здесь нет — только отпечатки. Подгонка невозможна: копировать нечего."}
```

- Сравнение по полям: `calibrate` отдаёт `{"field": "match" | "mismatch"}` и `facts_digest`.
- Прозу («что означает каждое поле и почему такой ответ правильный») — `docs/ЭТАЛОНЫ-ПОСЛЕ.md` в отдельном
  архиве `AgentContractKit-Calibration-0.1.36.zip`.
- Прямая оговорка в README и в `КАЛИБРОВКА.md`: файл с прозой читаем; недоступность — **порядок**, а не
  техническая защита. Кто открыл раньше — говорит об этом в отчёте.

### 3.5. Калибровочный цикл (как это происходит у вас)

1. `calibrate` — список промптов, что каждый проверяет, что считается ответом, чего не будет.
2. Агент выполняет промпт (K1…K4) и подаёт ответ: `calibrate submit` (JSON на stdin).
3. Инструмент **сначала записывает ответ** (через `plan`/`apply` в `local/calibration/`, с журналом), **потом**
   сравнивает и возвращает: `match` по полям, `facts_digest`, `environment`, `next`.
4. `calibrate report` — честный отчёт: что выявлено, что проверено, что исправлено, что осталось человеку,
   имеет ли смысл повтор, какие манипуляции с папкой доступны и что каждая значит.
5. `calibrate fix` — **закрытый список** безопасных починок: довести до конца незавершённую операцию,
   пересобрать `checks.json` из журнала, убрать свои временные файлы в `local/`. Всё остальное — `manual`.
6. Повтор предлагается, только если `match == false` и `reason == "data"`, и не больше одного раза.

### 3.6. `access` — права изнутри

`access` (чтение): для каждого из 9 путей записи — пробная запись в **свой** временный файл внутри
`.agent-contract/`, немедленное удаление в той же операции; данные проекта не touched.
Ответ: `{"path": {"writable": true, "reason": null}}`, `measured: true`, `writes: false` (в проекте ничего
не остаётся), и строка «права ОС комплект не выдаёт; он их измеряет».

### 3.7. README-вектор — структура

1. **Если вы пользователь** — 10 фраз из §2 и что произойдёт после каждой.
2. **Если вы агент** — 10 шагов `START`, калибровка, чего нельзя делать.
3. **Если вы проверяющий** — испытания, калибровка, эталоны, что считается `pass`.
4. **Границы и запреты** — 10 честных границ §4 и 17 правил §5 (по смыслу, без копипасты).
5. **Смыслы** — зачем каждый файл и каждая команда (таблица «файл → смысл», «команда → что доказывает»).
6. **Чего нет** — актуальный список `not run`.
7. **Оглавление и лимит 24 КБ**; каждое нормативное утверждение с якорем на источник.

## 6. Что осознанно не делаем

- **Не шифруем эталоны и не обещаем техническую недоступность.** В проектных файлах такой защиты нет (§4 п. 8).
  Дайджесты без значений — единственная честная гарантия.
- **Не даём агенту права менять базу или правила «для исправления».** Только закрытый список восстановлений.
- **Не сравниваем прозу.** Вердикт — по `facts`; проза объясняет человеку.
- **Не делаем автоматический мониторинг и фоновые прогоны** (§15: без отдельного согласия).
- **Не добавляем промптов «на все случаи».** Четыре — по числу разных входов и кодов отказа; остальное живёт
  в `PROTOCOL.md` и испытаниях.

## 7. Риски внедрения и как их ловим

| Риск | Проверка |
|---|---|
| эталон устарел относительно выпуска | сборка падает, если `system_version` эталона ≠ версии базы |
| калибровка проходит на «своём» ответе | L8: в поставке нет значений, только отпечатки; тест ищет значение эталона в архиве и падает, если найдёт |
| README врёт | тест якорей: утверждение без источника — fail; якорь в никуда — fail |
| `access` врёт про права | тест на каталоге только-для-чтения (`chmod`), ожидание `writable: false` |
| самоисправление выходит за границы | тест: `fix` не меняет базу, не меняет правила, не пишет вне `.agent-contract/` |
