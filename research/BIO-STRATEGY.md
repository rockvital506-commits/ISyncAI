# Пофазная стратегия формирования био-вселенной ISAI (BIO-STRATEGY)

Требование задания: «разработай пофазовую стратегию достижения целей, учитывая требования и
возможные мутации текущих сущностей ISAI», и «все фазы требуют подтверждения тестированием
мини систем».

Документ устроен так, что **каждая фаза заканчивается прогоном мини-системы**, а не
самооценкой. Итерация не считается завершённой, если её тест не исполнялся.

---

## 0. Исходные условия (измерено, не предположено)

| Факт | Значение | Источник |
|---|---|---|
| Био-символов в `.isai/` | **0** | grep |
| Био-символов в `research/lab/` | 6 | E6, E7 |
| Записей каталога | 22 (17 IMPLEMENTED, 3 PROSE, 2 MEASURED) | E8 + разметка |
| Числовых утверждений без артефакта | 30 из 32 | E8 M6 |
| Сущностей ниже порога 3 SLOC | 77.6% | E8 M2 |
| Стратегия кэша по каталогу | GLOBAL_EPOCH, hit 0.11 | E12 |
| Лучшая стратегия кэша | PER_PLASMID, hit 0.88 | E12 |
| Шлюз VM8 | был декларацией, теперь исполняется | `vector review` |

---

## 1. Принципы фазирования

**P1. Сначала измерение, потом перенос.** Био-вселенная не внедряется в `.isai/`, пока её
механизмы не проверены мини-системой. Перенос непроверенного — это не внедрение, а долг.

**P2. Каждая фаза имеет выход, который можно опровергнуть.** «Стало гармоничнее» — не выход.
Выход — число: hit_rate, FALSE_KILL, context_bytes, evidence_ratio.

**P3. Ветвление на каждой развилке.** У каждой фазы есть развилка с двумя исходами и
**заранее определённым** действием на каждом. Решение не принимается в момент развилки —
иначе оно принимается под давлением результата.

**P4. Мини-система — не демо, а инструмент отказа.** Тест мини-системы должен уметь
**провалиться**. E11 сначала не различал стратегии — это был провал теста, и он был исправлен.

**P5. Мутации сущностей ISAI учитываются заранее.** Каждая фаза объявляет, какие мутации
существующих символов она потребует, и что произойдёт, если мутация будет отклонена.

## 2. Фазы

### Фаза 0 — Консолидация знания (ВЫПОЛНЕНА в этом ответе)

**Цель:** устранить разрыв между прозой каталога и реальностью.

| Работа | Выход |
|---|---|
| Инвентарь био-вселенной | `BIO-INVENTORY.md` |
| Критический разбор 12 негативов | `BIO-CRITIQUE.md` |
| Проверка противоречий каталога | `CATALOG-CONTRADICTIONS.md` |
| Таблица имя → символ | `BIO-LEXICON.md` |
| Метрики M1..M6 | `results/e8_metrics.json` |
| Поле `maturity` + `evidence_ref` | `domain_models.py`, каталог размечен |
| Проверки H-KNOW-06/07 | `health_checks.py` |
| Исполняемый VM8 | `isai vector review` + 6 тестов |

**Мини-система:** E8 (метрики на живой вселенной) + E9/E10 (порог гранулярности).

**Выход фазы:** `evidence_ratio` = 0.125 → становится измеримым и отслеживаемым.
**Провал фазы:** если бы `maturity` не размежевался с `verified_revision`, фаза считается
несделанной — это была бы косметика.

---

### Фаза 1 — Проверка механизмов, от которых зависит всё остальное

**Цель:** установить, какие био-механизмы действительно работают, а какие являются прозой.

| Шаг | Действие | Метрика выхода |
|---|---|---|
| 1.1 | Проверить инвалидацию кэша четырьмя стратегиями | hit_rate ≥ 0.8 при stale=0 |
| 1.2 | Проверить апоптоз на ложные убийства | FALSE_KILL = 0 при context ≤ 600 Б |
| 1.3 | Проверить апоптоз каталога (зомби-записи) | 0 зомби из 22 |
| 1.4 | Проверить порог 3 SLOC | закон подтверждён или отозван |

**Мини-система:** E11 (апоптоз) + E12 (эпоха) + проверка ссылок каталога.

**Результат (уже получен):**

| Шаг | Итог | Вердикт |
|---|---|---|
| 1.1 | PER_PLASMID hit 0.88, GLOBAL_EPOCH hit 0.11 | **GLOBAL_EPOCH отозвать** |
| 1.2 | DISCRIMINATING: FUNCTION 100%, FALSE_KILL 0, context 556 Б | **принять** |
| 1.3 | 0 зомби из 22 | **страховка нужна, дефекта нет** |
| 1.4 | meso/nano 1.06x | **закон не подтверждён** |

**Развилка 1-A:** подтверждён ли порог 3 SLOC?
- **Да** → ввести правило апоптоза для вселенной, применить к 77.6% сущностей.
- **Нет (наш случай)** → отозвать закон, заменить на признак `stub` + тип сущности.

**Развилка 1-B:** какая стратегия инвалидации?
- PER_PLASMID → принять (наш случай: 0.88 и корректна).
- DEPENDENCY_DAG → принять, если в профиле доминируют зависимости (не наш случай: 0.35).

**Мутации, требуемые фазой:** ни одной в IL-0/IL-1C. Все изменения — в `research/` и в
каталоге (IL-2).

---

### Фаза 2 — Перенос проверенного в систему (требует ратификации)

**Цель:** перевести работающие механизмы из `research/lab/` в `.isai/` **по одному**, каждый
со своим тестом.

| Шаг | Что переносится | Куда | Тест |
|---|---|---|---|
| 2.1 | Инвалидация кэша PER_PLASMID | `.isai/bio_universe.py` | E12 как регрессия |
| 2.2 | Апоптоз с различением | там же | E11 как регрессия |
| 2.3 | Каталог: `maturity` + `evidence_ref` | уже сделано | H-KNOW-06/07 |

**Мини-система фазы 2:** `BIO_MINI` должна собрать RSoC-пакет для узла **через** новый
`.isai/bio_universe.py`, а не через `research/lab/`. Критерий: пакет совпадает с текущим
побайтово (иначе перенос изменил поведение).

**Развилка 2-A:** совпадает ли пакет?
- **Да** → перенос завершён, старый путь удаляется.
- **Нет** → перенос **откатывается** целиком; расхождение разбирается до повторной попытки.

**Мутации, требуемые фазой:** добавление `.isai/bio_universe.py` (IL-1 kernel).
**Если мутация отклонена:** фаза останавливается; `research/lab/` продолжает жить как есть,
и это документируется как «механизм проверен, но не внедрён» — честное состояние, не долг.

### Фаза 3 — Выравнивание каталога

**Цель:** довести `evidence_ratio` с 0.125 до ≥0.5, не выдумывая доказательств.

| Шаг | Действие | Метрика |
|---|---|---|
| 3.1 | Для каждого MEASURED — артефакт | 2/2 |
| 3.2 | Для каждого IMPLEMENTED — символ, названный в записи | 17/17 |
| 3.3 | Для каждого PROSE — помета «проект, не механизм» | 3/3 |
| 3.4 | Отозвать числа без артефакта | 30 → 0 |

**Мини-система фазы 3:** H-KNOW-06/07 + сверка, что каждая IMPLEMENTED-запись резолвится
в живой символ.

**Развилка 3-A:** что делать с непроверяемыми числами (110.7x, −59.2%, 2668x)?
- **Есть артефакт** → оставить как MEASURED.
- **Нет артефакта** → **отозвать число**, оставить качественное утверждение. Наш случай для
  30 из 32 утверждений: честнее сказать «сжимает контекст существенно», чем хранить
  невоспроизводимое «2668x».

**Мутации:** только IL-2 (каталог). IL-1C не затрагивается.

### Фаза 4 — Био-вселенная как часть системы

**Цель:** сделать так, чтобы био-механизмы были не экспериментом, а рабочим слоем.

| Шаг | Действие | Тест |
|---|---|---|
| 4.1 | Гены = сущности вселенной (не только синтетические) | 298 генов загружаются |
| 4.2 | Рибосома исполняет символы через существующий путь | результат совпадает с `load_module_attr_isolated` |
| 4.3 | Апоптоз на живой вселенной | 0 ложных убийств |
| 4.4 | Эпоха привязана к `Chronicle.revision` | инкремент ревизии инвалидирует кэш |

**Мини-система фазы 4:** полный прогон E8 на перенесённой вселенной. Критерий: M1..M6 не
хуже, чем на `research/lab/`.

**Развилка 4-A:** деградируют ли метрики?
- **Нет** → фаза принята.
- **Да** → откат 4.x, разбор конкретной метрики, повторная попытка только для неё.

**Мутации, требуемые фазой:** связывание эпохи с Chronicle — **мутация IL-1C**. Требует
6-шагового Алгедонического протокола и явной ратификации оператора. Без неё шаг 4.4 не
выполняется, остальные выполняются.

### Фаза 5 — Гармонизация (то, ради чего всё)

**Цель:** выполнить смысло-цель задания — «эффективная, гармоничная, структурированная
био-вселенная, бесшовно внедрённая».

| Критерий | Порог | Как измеряется |
|---|---|---|
| Эффективность | context на узел ≤ 600 Б при FUNCTION 100% | E11 |
| Гармоничность | 0 терминов без символа | BIO-LEXICON |
| Структурированность | 100% записей с maturity | H-KNOW-06 |
| Самодостаточность | 0 внешних зависимостей | E2, venv=0 влияния |
| Бесшовность | пакет RSoC побайтово совпадает | Фаза 2 |
| Доверие | evidence_ratio ≥ 0.5 | E8 M6 |

**Мини-система фазы 5:** сводный прогон E8 + E11 + E12 + H-KNOW как один отчёт.

## 3. Сценарное ветвление (полная карта)

| Развилка | Условие | Ветвь A | Ветвь B |
|---|---|---|---|
| 1-A | Порог 3 SLOC подтверждён при meso/nano > 1.5 | применить как закон | **наш случай (1.06)**: отозвать |
| 1-B | PER_PLASMID hit > DEPENDENCY_DAG hit | принять простую | **наш случай (0.88 > 0.35)**: принять PER_PLASMID |
| 1-C | FALSE_KILL DISCRIMINATING = 0 | принять | искать причину до внедрения |
| 2-A | Пакет RSoC совпал побайтово | перенос принят | **откат целиком** |
| 2-B | Мутация `.isai/bio_universe.py` ратифицирована | перенос | механизм остаётся в lab, документируется |
| 3-A | Артефакт существует | MEASURED | **наш случай (30/32)**: отозвать число |
| 4-A | Метрики не хуже | принять | откат шага, разбор |
| 4-B | Мутация IL-1C (эпоха ↔ Chronicle) ратифицирована | шаг 4.4 | шаг 4.4 отложен, остальное идёт |
| 5-A | Все 6 критериев достигнуты | цель достигнута | перечислить недостигнутые, не объявлять успех |

**Правило:** каждая ветвь B — это **не провал**, а штатный исход. Стратегия, у которой
провалом считается честный отказ, провоцирует подгонку чисел.

| Апоптоз убивает живое | уже случилось | потеря генов | FALSE_KILL как обязательная метрика |

## 5. Что НЕ делается и почему

| Не делается | Причина |
|---|---|
| Перенос био-символов в `.isai/` в этом ответе | требует ратификации (Фаза 2, развилка 2-B) |
| Мутация IL-1C (эпоха ↔ Chronicle) | требует Алгедонического протокола (4-B) |
| Применение DSL-фрагмента `[BIO-UNIVERSE]` | предложение, не применено (`BIO-LEXICON.md` §6) |
| Реализация Хромосом и Крио-архива | нет проверенного механизма; сначала Фаза 1 |
| Отзыв чисел из каталога | это Фаза 3, требует отдельного решения по 30 утверждениям |

**Почему:** каждая из этих работ меняет либо IL-1C, либо поведение системы. Задание требует
фиксации перспективных направлений и стратегии — оно не даёт права применять их без
ратификации. Стратегия ценна тем, что её можно исполнить, а не тем, что она уже исполнена.
