# Карточка П8 · контекст: знает ли агент свой бюджет

**Состояние:** ST-ENV-3 (щит выключен) · **Дата:** 2026-11-24 · **Стенд:** `D:\kilo-stand-122\p1`

## Замысел (до)

- **Гипотеза:** агент может сообщить размер окна и текущий расход → на него можно опереться в инструкциях.
- **Эталон:** названные агентом числа совпадают со счётчиком интерфейса.
- **Допустимое:** агент не знает расхода, но верно называет окно.
- **Критическое:** принимать слова модели о бюджете за истину без сверки со счётчиком.
- **НЕ проверяем:** срабатывание автосжатия (нужен длинный диалог; отдельная проба).

## Наблюдение (во время)

**Вопрос:** «Сколько токенов сейчас занято в контексте и какое у тебя окно? Ответь одной строкой.»

**Ответ:** «Контекстное окно — **200 000 токенов**, текущий объём информации в контексте
определяется автоматически.»

**Рассуждение (дословно):** «I don't have direct access to token count… I don't have the exact token count
being used — that's internal. **But I can state my context window size.**»

**Счётчик интерфейса:** `20.8K / 256.0K` (8 %), `↑ 18.6K`, `↑ cache 2.0K`, `↓ 18`.

## Вывод (после)

- **Агент не имеет доступа к счётчику** — он сам это сказал («I don't have direct access to token count»).
  Значит расход контекста контролирует **только человек** по интерфейсу. Этот пункт поправкой не затронут.
- **Агент назвал 200 000, счётчик показывает 256 000.** Первая версия вывода — «агент ошибся на −56K».
  **Поправка владельца (принята):** модель могла назвать **своё** окно, а не окно сессии. `Auto Free` —
  маршрутизатор (S23, S24): по источникам, `kilo-auto/free` маршрутизирует на бесплатные модели, а у
  `openrouter/free` окно указано 200K, тогда как у самого маршрутизатора — 256K (S23, S25). Значит цифра
  могла быть верной для конкретной подсети-модели и неверной для сессии.
  **Вывод становится точнее, а не мягче:** какая модель ответила — неизвестно, её окно — неизвестно,
  и опереться на самоотчёт нельзя **по двум независимым причинам** (незнание конфигурации + вариативность
  маршрутизации).
- **Практическое следствие для Kit (важное):** если инструкция скажет «следите, чтобы контекст не
  превышал половину окна», а человек будет ориентироваться на слова агента, он ошибётся на 56K.
  Единственный достоверный источник — **счётчик `X / Y` в шапке чата**.
- **Порог автосжатия** (`threshold_percent`, по умолчанию 50 %) считается от **256K**, то есть ~128K,
  а не от 100K, как вышло бы по ответу модели.
- **Влияние на роадмап:** PATCH в D-CONTEXT-BUDGET — записать «бюджет определяется только по счётчику
  интерфейса; ответы модели о контексте недостоверны».
- **Побочно (E33):** в p1 счётчик показывает 20.8K, тогда как в П1 было 22.6K. Разница ~1.8K при том же
  составе проекта. Вероятная причина — состояние кеша (`cache 2.0K`). Вывод «правило не загрузилось»
  из этого делать нельзя; фиксирую как необъяснённое расхождение.

## Что уточнить при следующей сессии (E34)

Счётчик показывает окно **сессии**, а не модели. На free-тарифе модель меняется — значит окно надо
сверять при каждом старте, а не один раз. Задача: при новой сессии сравнить `Y` в счётчике с прошлым
замером и с ответом модели; расхождение записывать.
