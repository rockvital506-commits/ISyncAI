# И‑110 · Ф2 · P0 — семь манипуляций × две области

**П0.** Чистый `57d7021`, remote совпал; [стратегия v1.11](../STRATEGY.md), A1–A4, P3/P11/P13, §3.3–3.5, Ф2, П0–П9/§7. Повтор печати [И‑109](../109/ACCEPTANCE.json) до правок точен. Есть карточки семи действий, но исполняется только L1 `rule/draft`. Замена текста или удаление ранее созданной записи несовместимы с журналом И‑106 в его прежней форме: он проверяет хвост живых черновиков, а не последовательность изменений. Нужна новая форма контейнера **без** изменения v2 и без второго файла записи. Это работа И‑110, не перенос/миграция из 0.1.36, диалог И‑111 или bootstrap И‑112.

**П1. Гипотеза.** Все 14 пар `register/create`, `list`, `edit`, `suspend`, `resume`, `revoke`, `delete` × L1/L2 работают через карточку. Просмотр не пишет. Мутация меняет ровно выбранный файл и его ревизию по билету на точный дифф; история доступна при повторном чтении. Отказ, повтор без изменения и `no_change` не меняют ни байты, ни решения.

| Решение | Основание и граница |
|---|---|
| Реестр допуска открывает семь действий для L1/L2, оставляет `read` внутренним для L0/L1/L2 и все мутации L0 запрещёнными. `register` в стратегии — операция `create` карточки, не второй маршрут. | 14 **реальных** вызовов, не только строки матрицы. Реквизиты по-прежнему из И‑108, доверенная привязка L1 отдельно. L0 `list` через карточку ещё не подключён; внутреннее чтение сохранено. |
| `create` регистрирует черновик любого из пяти видов v2, не действие агента. Дочерние виды требуют существующего локального `contract` и вложенного `scope`. `edit` меняет только явно указанный `text` у не отменённой записи; ID, вид, родитель, область, основание и критерий остаются. | Нет скрытой активации, нового действия `activate` или изменения состояния через `edit`. Карточка хранит прозвучавший вид; подстановка другого вида по ID запрещена. Имена/ID из соседней области не разрешаются. |
| `suspend: active→suspended`, `resume: suspended→active`, `revoke: draft/active/suspended→revoked`; точный повтор состояния — `no_change`. Активируемая через `resume` дочерняя запись требует активного родителя. | Прочие переходы — `invalid_transition`; `revoked` не оживает. Состояния дочерних строк не меняются каскадно. `list` выдаёт каталог выбранной области (тело — только по `view:text` и ID); фильтр «действующие» исключает неактивного родителя. Это не слитый эффективный набор и не проверка соблюдения правил. |
| Физическое `delete` только у `revoked` и с отдельным `allow_delete is True` в `apply` **помимо** билета. Никакого каскада, родитель с любыми детьми — `parent/contract_has_children`. | `delete_confirmation_required` не подменяется фразой «удали» или числом 1; билет проверяется повторно при реальной записи. Отмена хранит содержание, удаление убирает его из текущего реестра. Локальный журнал оставляет ID и хеши; это не удаление истории Git/копий. ID, удалённый в наблюдаемом журнале, не используется повторно (`entry_retired`). |
| Одна подготовка/запись, прежние проверки И‑109 и A1–A4. Проверяются существующие и **будущие** структурные противоречия, включая `resume`; при конфликте показаны обе строки. | Нет выбора победителя или разрешения — И‑116. Отдельный билет и свежие SHA‑256 трёх реестров, `revision` **целевой** области, хеш и байты результата. Разрешённый маршрут пишет только свой файл; ожидаемые `stale_revision`, `stale_plan`, `plan_mismatch`, `write_failed` не размываются. |
| Однофайловый `registry_format: 2` для истории манипуляций L1/L2. `base_revision`, карта исходных ID→SHA‑256, ряд проверяемых переходов `before_sha256→after_sha256` и `profile_revision`/`project_revision`. | Голый v2 читается без перезаписи, его базовая карта — наблюдаемое состояние. Из L1 `profile_format: 1` переносятся **реально известные** решения `create` и их отпечатки; старый путь L1 `rule/draft` до других изменений сохраняет старую форму. Валидируем непрерывность, одно действие с ID за шаг и совпадение последней карты с реестром. Это не архив прежних тел, не подпись и не защита от подмены всей истории. L0 без контейнера. |

**П2 до кода.** [CASES.json](CASES.json), [test_actions.py](test_actions.py): все 14 ячеек с точным результатом/байтами и обязательные контроли состояний, локальности, отдельного согласия, стабильности плана, no-change, истории и отказа замены. Положительная запись проверяется по независимо построенному контейнеру и прочитанному журналу, наблюдаются замены, попытки записи и изменения путей; реальные L0 и чужой слой в каждом временном дереве неизменны. В П2 0 обязательных случаев могут быть `not run`. Изменения подготовительных фикстур до наблюдения не считаются действиями порта.

**П3–П5.** Два отдельных процесса checkout/чистый снимок только указанных входов, никакого ISAI/донора. Приёмка требует точного `7×2`, всех обязательных ID и кодов, 0 fail, согласованного журнала, ни одного побочного изменения и совпадения наблюдений. Ошибка исполнения не повод менять критерий. Linux/один писатель; не тест прав среды, гонок, ACL/NTFS, сбоя питания, удаления из внешних копий.

**П6–П9.** Отчёт (`basis`/`criterion`), ZIP с приёмкой, read-only повтор, страница, сверка и commit/push. Откат разработки — отмена коммита, пробы — временные. Не начинаем И‑111, И‑112, разрешение конфликтов, активацию действующего профиля, `R-2`, промоушен, перенос, миграцию и живые адаптеры. Архивы предыдущих итераций не переписываются.
