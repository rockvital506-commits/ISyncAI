# И‑048 · Два сценария рядом — отчёт

18 ноября 2026. Выпуск **0.1.28**. Итерация закрывает §15 в части «сравнение двух сценариев»: наборы
сравниваются по действующему, а не по реестру, и опознаются смыслом, а не `id`.

## Что появилось

| Правило | Ответ |
|---|---|
| вход | `metrics {"against": "<путь ко второму проекту>"}`; без `against` — прежний ответ |
| сравнивается | `active`-правило под `active`-контрактом обеих сторон, в пределах `target` |
| опознание правила | `key`+`scope` для структурного факта, `text`+`scope` для свободного правила |
| `same` | те же факты в обоих сценариях |
| `changed` | тот же `key` и `scope`, другое значение: `values_here`, `values_there`, `here`/`there` — `id` |
| `only_here`, `only_there` | чего нет в другом сценарии — поимённо, с `bytes` |
| `cost` | `bytes_here`, `bytes_there`, `delta = bytes_here − bytes_there` |
| `noise` | сколько `draft`/`suspended` с каждой стороны (в сравнение не входят) |
| чужая сторона | отказ `compare` с `{against, reason, details}`: `root`, `drift`, `conflict`, `schema`, `missing` |
| чтение | `writes: false`; сравнение не меняет ни байта |

## Замечание по ходу

Первая версия правки читала `against` из консоли, но `main` не включал `metrics` в список команд,
читающих stdin, — из консоли параметр молча терялся. Поймано стендом `L4K` (не тестами: тесты вызывают
`dispatch` напрямую). Правка вошла в выпуск: `metrics` теперь в списке команд с входом.
