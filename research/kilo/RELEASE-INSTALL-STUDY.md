# Эксперимент установки из подписанного архива `.76a`

Это исследовательский Python API, **не готовый установщик и не доверенная доставка**.
Заранее доверенными предполагаются весь исполняемый checkout (включая `kit` и модули
`research/audit`), Python, криптографический callback, политика, ключи и checkpoint.
Подпись фиксирует bytes согласно `RELEASE-POLICY-STUDY.md`; она не подтверждает смысл L0,
источник политик, независимое ревью или полномочия человека.

`InstallSession` принимает архив/заявление/подпись в памяти, внешнюю политику и проверяющий
callback, абсолютный путь **нового** контейнера и корень профиля. Проверяет архив и затем
строит новый L0/L1/L2 по доверенному коду и L0 из проверенных bytes. Результат — одно дерево
с раздельными `snapshot` и `workspace`. Полный план содержит имена и хеши всех файлов,
данные о политике, корни, выбранный профиль и случайное имя стадии. Никакая запись не
происходит до отдельного подтверждения точного плана; билет сам не доказывает согласие.
Успех — `study_container_published_unverified_origin`, не практическая приёмка.

Используется `PublishSession`: Linux/POSIX, `renameat2(NOREPLACE)`, закрытый состав, fsync,
кооперативная блокировка родительского inode, повторная проверка перед/после rename. Новое
имя не перезаписывается; стадия не удаляется автоматически. При ошибках сохраняется код
нижнего слоя, после попытки rename `publication_unknown`: не повторять и не удалять вслепую.
`os._exit`, гонки сторонних процессов, поломка питания, network FS, метаданные и mount-алиасы
не доказаны этой интеграционной пробой; прочие ограничения — в `RELEASE-ARCHIVE-STUDY.md`.

Проверки `python3 -I -S -B research/audit/test_release_install_study.py -v`: синтетический
подписанный кандидат, полный план, подтверждение, bootstrap и два режима; занятая цель,
неверный профиль/подпись/билет, изменение плана или профиля, отмена, повтор билета и
инъекция ошибки rename. Проверяются реальные операции в временной директории, но не внешние
среды, независимый владелец, работа с ценными данными и надёжность системы после отказа питания.
Наблюдение и восстановление этого комбинированного контейнера пока не реализованы; до `.77`
никаких автоматических повторов/удалений. `kit` версии `.72` не изменён, G1–G6 открыты.
