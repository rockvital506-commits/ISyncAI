# План серии проб: каждая проба — отдельный шаг со своим итогом

**Дата:** 2026-11-22 · **Основание:** замечание владельца «каждая проба — итерация, не сваливать в кучу»

## 1. Что берём из замечания (по сути)

Если сложить восемь проб в один заход, теряются:
- промежуточные наблюдения (что видел между шагами);
- ошибки (где сломалось и на чём именно);
- основания в��водов (из чего следует вывод).

Значит каждая проба оформляется как **мини-итерация** с пятью полями: замысел (до), наблюдение
(во время), вывод (после), статус, влияние на роадмап.

## 2. Шаблон карточки пробы (единственный формат)

```markdown
## П<n> · <название>
Состояние: ST-... | Среда: VSCode 1.147.0 / Kilo 7.8.32 | Дата:

**Замысел (до)**
- Гипотеза: <что ожидаем, со ссылкой на KILO-SPEC / документацию>
- Что считается эталоном: <проверяемое описание>
- Допустимое отклонение: <что не опровергает гипотезу>
- Критическое отклонение: <что останавливает>
- Что НЕ проверяем: <границы>

**Наблюдение (во время)**
- Сделал: <одна строка>
- Видно: <дословно, без интерпретации>
- Не видно: <чего не было>
- Артефакт: <скрин, SHA-256, вывод команды>

**Вывод (после)**
- Уровень: обнаружен / прочитан / применён / повторяется / not observed / inconclusive
- Подтвердилось: <да/нет/частично> — против какой гипотезы
- Новая находка: <или «нет»>
- Влияние на роадмап: не требуется / MINOR / MAJOR (с причиной)

**Статус**: pass / not observed / inconclusive / blocked
```

## 3. Правила серии

1. **Одна проба — одна карточка.** Даже если она заняла 2 минуты.
2. **Между пробами пауза:** я читаю карточку и говорю «продолжай» или «переделай». Так промежуточный
   вывод не теряется.
3. **Ошибка — тоже результат.** Если что-то сломалось, карточка заполняется, а не пропускается.
4. **Порядок жёсткий:** P00 → П1 → П2 → П3 → П4 → П5 → П6 → П7 → П8. Причина: П1 без P00
   измеряет неизвестно что; П6 бессмыслен без П2.
5. **Влияние на роадмап** фиксируется в каждой карточке, даже если «не требуется». Это ответ на
   «не забывай сверять ориентир».

## 4. Что будет после каждой пробы

| После | Что я делаю | Что появляется |
|---|---|---|
| P00 | проверяю отпечаток: версия, провайдер, модель, права, старт сеанса | состояние `ST-ENV-1` уточнено |
| П1 | сравниваю «канарейка» + «вкладка Правила» | закрытие/уточнение C1 |
| П2 | сравниваю с П1 | C1 закрыт в сторону документации или наоборот |
| П3 | сверяю SHA‑256 до/после | `entry_mode: foreign` подтверждён или опровергнут |
| П4 | проверяю, что `sample.txt` не изменился | права агента подтверждены |
| П5 | смотрю причину автоодобрения | порядок правил подтверждён |
| П6 | отделяю reload от новой сессии | E14 закрыт |
| П7 | сравниваю два состояния мастера | C11, C12 |
| П8 | фиксирую модель и окно | E16, вход в И‑126 |

## 5. Что из этого станет И‑122

- Восемь карточек = восемь «входов» итерации.
- RED: до выполнения обязательных проб И‑122 в состоянии `не выполнено`.
- GREEN: все обязательные карточки заполнены, ни одна не `inconclusive` без причины.
- Печать и отчёт — только после этого, по общему протоколу П7–П9.

## 6. Чего не будет

- Не будет «сводной пробы на всё»: она даёт ложную уверенность.
- Не будет вывода по одной карточке: N=1 — это наблюдение, не доля.
- Не будет подмены: «агент сказал, что прочитал» — не уровень «прочитан».
