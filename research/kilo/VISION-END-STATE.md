# Видение итога: что именно должно получиться

**Дата:** 2026-11-22 · **Основание:** запрос владельца на структурированное определение итога
**Связь:** `TARGETS.md` (эталон / допустимое / критическое), `ROADMAP-PROTOCOL.md` (права на правки)

> **Действующий ориентир:** [ROADMAP.md](ROADMAP.md), версия 4.0.0. Ниже историческое видение с уточнёнными владельцем G5 и смыслом перемещения; при расхождении ориентир имеет приоритет.

## 1. Три горизонта «итога» — их нельзя смешивать

| Горизонт | Что это | Когда считается достигнутым |
|---|---|---|
| **Итог проекта** | выпуск 0.2.0: переносимая система контрактов | ворота G1–G6 (см. §6) |
| **Итог фазы** (сейчас Ф5) | адаптеры трёх сред с честными статусами | у каждой среды `status` + пробелы; старшинство хотя бы у одной — по факту |
| **Итог текущей задачи** | досье Kilo + подготовленная среда + серия проб | P00 выполнен, П1–П8 записаны отдельными карточками |

## 2. Характеристики итога (что значит «качественно»)

Восемь атрибутов. У каждого — определение и способ проверки. Без проверки атрибут не считается.

| # | Атрибут | Определение | Как проверяется |
|---|---|---|---|
| K1 | **Переносимость** | новый владелец и посторонний агент начинают по документу, без автора | прогон И‑138: посторонний агент инициализируется по README/INIT‑PROMPT |
| K2 | **Проверяемость** | каждое утверждение имеет `basis` и `criterion`, а не «работает» | выборочная сверка отчётов: доля утверждений без basis |
| K3 | **Воспроизводимость** | результат повторяется из снимка: архив, печать, повтор | `--verify-seal` на каждой итерации |
| K4 | **Безопасность** | права ограничивают **действия агента**; попытки видимы, включая делегированные; секреты не попадают в **реестр Kit** | `deny` на **набор** правил (`edit`+`task`) + сверка хешей. **Не** проверяется «агент не может прочитать .env» (П7) и «запрет записи непреодолим» (E27: субагент пишет) |
| K5 | **Поддерживаемость** | обновление собственного Kit и восстановление не теряют согласованных сущностей | И‑130/131 на копии |
| K6 | **Минимальность контекста** | вход дешёвый относительно **фактического** окна | И‑126: измеренные токены ≤ 25–30 %; окно берётся со счётчика интерфейса, а не из ответа модели (П8: 20.8K из 256K = 8 %) |
| K7 | **Честность статусов** | `not run` ≠ `pass`; `candidate` не выдаётся за рабочий | приёмка П5: пропуск обязательного не даёт `accepted` |
| K8 | **Раздельность слоёв** | L0/L1/L2 не смешиваются, адаптер не становится вторым реестром | A1–A4 + проверка, что производный материал не стал вторым реестром |

| Ф4 | «покажи правила» | чтение L0/L1/L2 с раздельными правами, L0 неизменяем | И‑104–107 | многопользовательский доступ, ACL |
| Ф5 | «перенеси правило в общий профиль» | план обеих сторон, имитация в двух проектах, просмотр конфликтов, подтверждённое перемещение с удалением источника | И‑114–116 | автоматический выбор победителя |

## 4. «Первый день» после 0.2.0 — проверяемый сценарий

1. Клонировать репозиторий, открыть в VS Code.
2. Прочитать README → вставить INIT‑PROMPT в агент.
3. Агент спрашивает ≤3 вопроса, показывает план, получает «да».
4. Появляется `.agent-contract/project/registry.json` и запись правила.
5. `guard` в коммите подтверждает, что L0 не тронут.
6. Второй проект: тот же профиль, правило видно, но не активно, пока владелец не подтвердит.

Критерий: всё это занимает < 10 минут и не требует автора проекта.

## 5. Что останется недоказанным даже в 0.2.0 (честный список)

- Поведение сред, которые недоступны для прогона: только `not run` с причиной.
- Доли применения правил за пределами N прогонов И‑125.
- «Доверие» в смысле организационном: подпись доказывает ключ, не человека.
- Работа в чужих проектах: Kit их не трогает.
- Любые обещания про модели: модель ≠ поверхность продукта; на free-тарифе модель ещё и меняется между сессиями.
- «Секреты не утекут»: правила Kilo ограничивают инструменты, а не данные (П7). Обещается видимость попыток и отказ
  при выключенном мастере автоодобрения — не сохранность секретов.
- «Точку входа нельзя изменить»: `AGENTS.md` не защищён от записи (П3); целостность — только внешним контролем (хеши, откат).

## 6. Ворота приёмки итога

| Гейт | Что проверяется | Источник |
|---|---|---|
| G1 | полный срез: пакет собирается и проверяется | И‑117, 118 |
| G2 | доверие и откат | И‑119, 120 |
| G3 | принуждение без модели | И‑127, 128 |
| G4 | пригодность сред с числом прогонов | И‑125, 137 |
| G5 | обновление собственного Kit без потери сущностей и восстановление на копии; миграция донора не требуется | И‑130–132 |
| G6 | новый владелец начинает без автора | И‑138, 140 |

Итог достигается только при G1–G6. Любой пропуск — `not run`, а не «достигнуто с оговоркой».

## 7. Антипримеры (как выглядит недоделка)

- «Работает» без числа прогонов и без названной среды.
- `candidate`, выданный за рабочий адаптер.
- Правила скопированы в среду и стали вторым реестром.
- Критерий ослаблен после `fail`.
- Досье или отчёт без даты и источника.
- «Тесты зелёные», но обязательные пробы не выполнялись.
