# Исследовательский локальный и CI-контур `.83a`

`research/audit/ci_gate_study.py` последовательно выполняет проверку локального кандидата с
явным pin манифеста, guard указанного полного Git tree/commit OID, статические инвентари,
локальные L0-аудиты и core audit, затем каждый `research/audit/test_*.py` в отдельном
`python3 -I -S -B` процессе. Ошибка, timeout, ноль обнаруженных тестов, пропуск или несогласие
инвентаря вызывает ненулевой код. Пример на чистом checkout:

```sh
python3 -I -S -B research/audit/ci_gate_study.py --tree "$(git rev-parse HEAD^{tree})"
```

Workflow `.github/workflows/candidate-check.yml` вызывает ту же команду для checkout на
`ubuntu-latest`; разрешение токена ограничено чтением содержимого, сохранение credentials в
checkout выключено, checkout action закреплён по полному SHA. Сам файл workflow не доказывает,
что GitHub Actions запустился или прошёл: до фактического наблюдения CI `not_run`.

**Граница доверия:** verifier, guard, тесты, Python и исполняемые системные программы запускаются
из проверяемого checkout/среды, а не из независимо удостоверенного bootstrap. Указанный pin
является локальной привязкой к кандидату `.72`, не доказательством происхождения или допуска
нового релиза. Git tree guard проверяет L0 кандидата, а не весь исполняемый путь и не все API.
Проверки — синтетические и не закрывают G3, средовые испытания, независимое ревью, семантику,
реальные данные, права или безопасность checkout. Не запускать код недоверенного checkout с
секретами или повышенными полномочиями. Перечень тестов формируется динамически; по нему не
следует делать вывод о полноте покрытия. Бюджет контекста и два режима отдельно описаны в
`ENVIRONMENT-OBSERVATION-CARDS.md`, наблюдения целевых сред остаются `not_run`.
