# Карточка П5 · разрешения: `"*": ask` и точечный `allow` (щит ВЫКЛЮЧЕН)

**Состояние:** ST-ENV-3 (мастер автоодобрения **выключен**) · **Дата:** 2026-11-24
**Стенд:** `D:\kilo-stand-122\p5` — `.kilo\agents\exec.md`:
`edit: deny`, `bash: {"*": "ask", "git status*": "allow"}` · агент отображается как **`Exec`**

## Замысел (до)

- **Гипотеза:** при выключенном мастере действует модель прав: точечное `allow` пропускает без вопроса,
  остальное попадает в `ask`.
- **Эталон:** `git status` без вопроса + `git log` с вопросом.
- **Допустимое:** обе спрошены (правило не сработало) или обе без вопроса (`ask` не действует).
- **Критическое:** засчитать «правило сработало», не увидев формулировку причины.
- **НЕ проверяем:** что сильнее — «последнее совпадение» или «более конкретное правило».
  Этот прогон **не различает** эти две модели (см. «Ограничение методики»).

## Наблюдение (во время)

**Щит:** подсказка «Автодобрение отключено. Нажмите, чтобы автоматически одобрять запросы разрешений.
Запросы на выход из песочницы всегда исключены.» → мастер выключен, подтверждено.

**1) `git status` — без вопроса.** Подпись:
> **«Одобрено автоматически агентом exec.md совпало с правилом "bash" "git status*"»**

Это **отдельная формулировка**, отличная от «Одобрено вами» (P3) и от «совпало с правилом» в p4:
интерфейс называет источник правила **по имени файла агента**. То есть при правиле-`allow` журнал
показывает правду.

Вывод команды: `fatal: not a git repository (or any of the parent directories): .git`
(p5 — не git-репозиторий; на срабатывание правила это не влияет, но фиксирую честно).

**2) `git log --oneline -1` — запрос.** Окно «Требуется разрешение / Show last commit»
с кнопками `Разрешить один раз` / `Запретить` и ссылкой `Управление правилами автодобрения`.
Одобрено → «Одобрено вами» → та же ошибка `fatal: not a git repository`.

**3) `ls -la` — запрос** (агент сам решил проверить каталог). Одобрено → **ошибка**:
`Get-ChildItem : Не удается найти параметр, соответствующий имени параметра "la"` +
`InvalidArgument … ParameterBindingException`.

**4) Агент сделал вывод:** «This is PowerShell, not bash. Let me use the proper PowerShell command.»
Затем `Get-ChildItem -Force` → запрос → одобрено → список: только `.kilo`.

**Ответ пользователю:** «Not a git repository. Current directory (D:\kilo-stand-122\p5) only contains .kilo/.»

**Токены:** 20.3K → 20.4K → 20.8K / 256.0K (8 %).

## Вывод (после)

- **Уровень: применён.** Точечное `allow` пропустило команду без вопроса, остальное попало в `ask`
  (три запроса подряд — ровно те три команды, что не подошли под шаблон).
- **Подтверждена гипотеза владельца:** при **выключенном** щите работают **свои** настройки автоодобрения.
  При включённом (P3/P4) они не видны: ask не спрашивает.
- **Иерархия состояний уточняется:**
  | Щит | `allow` | `ask` | `deny` |
  |---|---|---|---|
  | выкл | без вопроса | спрашивает | запрещает |
  | вкл | без вопроса | **не спрашивает** | запрещает |
- **НОВАЯ НАХОДКА (C24): инструмент `bash` исполняет команды в PowerShell.** Команда `ls -la` из
  bash-синтаксиса провалилась с `ParameterBindingException`. Для Kit это значит: любые примеры команд
  в инструкциях должны быть либо PowerShell-совместимыми, либо обёрнутыми, иначе агент будет падать
  на пустом месте, а пользователь решит, что сломан Kit.
- **Журнал (для аудита):** три разных подписи — «Одобрено автоматически агентом exec.md совпало с
  правилом …» (правило), «Одобрено вами» (человек), «Одобрено вами» (мастер, P3 — **ложь**).
  Различать можно только по первой формулировке.

## Ограничение методики (честно)

Шаблоны `*` и `git status*` **перекрываются**: команда `git status` подходит под оба. Поэтому исход
`allow` объясняется и моделью «последнее совпадение в файле», и моделью «побеждает более конкретный
шаблон». Этот прогон **не различает** их. Нужна обратная запись: сначала `allow`, потом `*` → см. П5-доп.

## Добивка П5-доп (обратный порядок)

**Файл:** `bash: { "git status*": allow, "*": ask }` — точечное правило **первым**, затем общий `ask`.
**Команда:** `git status`. **Результат:** **без вопроса**, подпись та же —
«Одобрено автоматически агентом exec.md совпало с правилом "bash" "git status*"».

**Вывод:** порядок записей **не влияет**. Модель «побеждает последнее совпадение» **опровергнута**.

## Добивка П5-доп-2 (обратная комбинация)

**Файл:** `bash: { "*": allow, "git status*": ask }` — общий `allow`, точечный `ask`.
**Команда:** `git status`. **Результат: ЗАПРОС.** Окно «Требуется разрешение / Show git working tree status»,
кнопки `Разрешить один раз` / `Запретить`. Владелец **не нажимал** разрешение.

**Вывод: побеждает более конкретный шаблон.** `ask` перекрыл `allow`. Гипотеза «allow сильнее ask
независимо от шаблона» **опровергнута**.

**Итоговая модель прав (наблюдённая):**
| Свойство | Наблюдение |
|---|---|
| приоритет при перекрытии | **конкретность шаблона**, не порядок в файле |
| порядок записей | не влияет |
| `deny` | сильнее мастера автоодобрения |
| `ask` | работает при щите ВЫКЛ; при щите ВКЛ не спрашивает |
| имена | `bash` = PowerShell |

Для Kit это удобная модель: точечными правилами можно и разрешать, и спрашивать, и запрещать.

**Токены:** 15.8K / 256.0K (6 %) — новая сессия в p5.
