# Карточка E25 · конфликт `AGENTS.md` и `.kilo/rules/` — кто побеждает

**Тип:** обязательная проба (закрывает последний `not run` И‑122; вопрос **установки**, не защиты)
**Дата:** 2026-11-24 · **Стенд:** `D:\kilo-stand-122\p8` (новый, чтобы не смешивать с p1/p2/p3)
**Состояние:** мастер автоодобрения **ВЫКЛ** (`ST-ENV-3`), агент `Code`, модель `Auto Free`

## Замысел (до)

- **Гипотеза:** два источника правил с разными значениями одной строки конфликтуют предсказуемо,
  и победитель известен. Без этого Kit не может решить, ставить одну точку входа или две.
- **Эталон:** назван победитель + указан признак, по которому это видно (в рассуждении агента
  источник назван поимённо).
- **Допустимое:** агент цитирует **оба** значения и не выбирает — тогда фиксирую «конфликт не решается,
  Kit обязан ставить один источник».
- **Критическое:** засчитать победителя по догадке из документации, не увидев, откуда агент взял строку.
- **НЕ проверяем:** приоритет с `instructions` в `kilo.jsonc` (это p2, отдельный вопрос) и защиту проекта.

## Подготовка стенда (3 минуты)

**1.** Создайте папку `D:\kilo-stand-122\p8\.kilo\rules`.

**2.** Файл `D:\kilo-stand-122\p8\AGENTS.md`:

```markdown
# Указатель проекта
Строка проверки: ENTRY-FROM-AGENTS
```

**3.** Файл `D:\kilo-stand-122\p8\.kilo\rules\entry.md`:

```markdown
# Правила проекта
Строка проверки: ENTRY-FROM-RULES
```

**4.** `Файл` → `Открыть папку…` → **`p8`** → `Ctrl+Shift+P` → `Developer: Reload Window`.
Агент — **`Code`**, щит **выключен** (подсказка «Автодобрение отключено»).

## Действия (два вопроса, оба обязательны)

**Вопрос 1 — что в контексте:**

```
Не читая файлов, перечисли дословно все строки, содержащие ENTRY-. Для каждой укажи, из какого
источника она пришла. Если источник не знаешь — так и скажи.
```

**Вопрос 2 — кто побеждает при выборе:**

```
Если бы тебе нужно было назвать ровно одно значение вместо ENTRY- — какое бы ты выбрал и почему?
```

## Что прислать

```
вопрос 1 — все строки ENTRY- с источниками: <дословно>
вопрос 2 — выбранное значение и причина: <дословно>
был ли запрос разрешения: да/нет
токены: <X / Y из счётчика>
```

## Как я прочитаю результат

| Исход | Что записываю | Что это значит для Kit |
|---|---|---|
| видны **обе** строки, победитель назван с источником | приоритет существует и наблюдаем | можно ставить **две** точки входа, зная порядок |
| видны обе, победитель **не** назван / выбор произволен | **конфликт не решается** | Kit ставит **один** источник; второй запрещён правилом проекта |
| видна **только одна** строка | второй источник **не подхвачен** | это не конфликт, а «один источник побеждает молча» — самый опасный исход: правило пользователя теряется без предупреждения |

**Третий исход я не смягчу.** Если `AGENTS.md` молча вытесняет `.kilo/rules/`, то владелец чужого
проекта, у которого уже есть `AGENTS.md`, **не увидит** правил Kit вообще — и решит, что Kit не работает.

## Почему именно так

- Вопрос 1 просит **источник** у каждой строки: без этого нельзя отличить «победил» от «второй файл
  вообще не прочитан».
- Вопрос 2 — единственный способ увидеть **приоритет в действии**: модель почти всегда выберет одну
  строку, и важно, сошлётся ли она на источник или угадает.
- «Не читая файлов» убирает `grep`: иначе мы измерим поиск, а не содержимое системного промпта.

## Вывод

- **Уровень: применён (конфликт разрешён в пользу `AGENTS.md`)** — но не «победой правила», а тем, что
  **второй источник вообще не попал в контекст**.
- **Третий исход из плана карточки: `.kilo/rules/` молча вытеснен.** В системном промпте — только
  `Instructions from: …\p8\AGENTS.md`. Файла `.kilo/rules/entry.md` там нет.
- **Это поправляет мой вывод из П1.** В П1 каталог `.kilo/rules/` подхватился автоматически — но там
  **не было `AGENTS.md`**. Здесь, при наличии `AGENTS.md`, тот же каталог **не загружен**.
  Корректная формулировка: **автоподхват `.kilo/rules/` работает, пока в проекте нет `AGENTS.md`;
  при наличии `AGENTS.md` каталог молча игнорируется.**
- **Молча** — ключевое слово: ни предупреждения, ни записи во вкладке «Правила» (не проверялось),
  ни намёка в ответе. Владелец чужого проекта с существующим `AGENTS.md` не увидит правил Kit вообще
  и решит, что Kit не работает.

## Что это значит для Kit (меняет устройство установки)

| Вариант | Когда годится |
|---|---|
| `.kilo/rules/` как единственная точка входа | **только** если в проекте **нет** `AGENTS.md` |
| короткий указатель **в** `AGENTS.md` | если `AGENTS.md` уже есть — иначе правила не попадут в контекст |
| `instructions` в `kilo.jsonc` | требует проверки: загрузит ли он `.kilo/rules/` при наличии `AGENTS.md` (`E36`) |

**Одной универсальной точки входа нет.** Установщик Kit обязан **сначала посмотреть**, есть ли
`AGENTS.md`, и выбрать механизм по факту — а не по документации.
