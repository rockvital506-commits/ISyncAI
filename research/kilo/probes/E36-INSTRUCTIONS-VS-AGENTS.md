# Карточка E36 · загрузит ли `instructions` каталог правил при наличии `AGENTS.md`

**Тип:** обязательная проба (последний неизвестный, от которого зависит текст установки Kit)
**Дата:** 2026-11-24 · **Стенд:** `D:\kilo-stand-122\p8` (тот же, что в E25 — там уже есть оба источника)
**Состояние:** мастер автоодобрения **ВЫКЛ**, агент `Code`, модель `Auto Free`

## Замысел (до)

- **Гипотеза (проверяемая):** запись `instructions: [".kilo/rules/*.md"]` в `kilo.jsonc` заставит Kilo
  загрузить каталог правил **даже при наличии `AGENTS.md`**. Если так — появится **универсальный**
  механизм установки, работающий в любом проекте.
- **Эталон:** в системном промпте появляются **обе** строки — `ENTRY-FROM-AGENTS` и `ENTRY-FROM-RULES` —
  и агент называет **два разных источника**.
- **Допустимое:** `ENTRY-FROM-RULES` не появился → `instructions` не преодолевает `AGENTS.md`;
  установщик обязан различать два случая.
- **Критическое:** засчитать «работает», если агент прочитал файл **инструментом** `read`, а не получил
  его в системном промпте. Это разные вещи: первое — поиск, второе — загрузка правил.
- **НЕ проверяем:** приоритет при конфликте значений (это сделано в E25) и защиту проекта.

## Почему тот же стенд `p8`

`p8` уже содержит ровно нужную комбинацию:
- `AGENTS.md` со строкой `ENTRY-FROM-AGENTS` (в контексте оказалась только она — E25);
- `.kilo/rules/entry.md` со строкой `ENTRY-FROM-RULES` (в контекст не попала — E25).

Добавляем **одну** вещь — `kilo.jsonc`. Всё остальное неизменно, поэтому разница в результате
будет вызвана **только** этой записью.

## Подготовка (2 минуты)

**1.** Создайте `D:\kilo-stand-122\p8\kilo.jsonc`:

```jsonc
{
  "$schema": "https://app.kilo.ai/config.json",
  "instructions": [".kilo/rules/*.md"]
}
```

**2.** Убедитесь, что файлы на месте (их не меняли с E25):
- `p8\AGENTS.md` → `Строка проверки: ENTRY-FROM-AGENTS`
- `p8\.kilo\rules\entry.md` → `Строка проверки: ENTRY-FROM-RULES`

**3.** `Ctrl+Shift+P` → `Developer: Reload Window`. Без этого проектный `kilo.jsonc` не подхватится.

**4.** Проверьте: открыта папка **`p8`**, агент **`Code`**, щит **выключен**.

## Действия

**Вопрос (тот же, что в E25 — иначе результаты не сравнить дословно):**

```
Не читая файлов, перечисли дословно все строки, содержащие ENTRY-. Для каждой укажи, из какого
источника она пришла. Если источник не знаешь — так и скажи.
```

**Затем откройте** шестерёнка → `Поведение агента` → вкладка **«Правила»** и сфотографируйте её.

## Что прислать

```
все строки ENTRY- с источниками: <дословно>
сколько источников назвал агент: 1 / 2
вкладка «Правила»: <что перечислено: пути>
токены: <X / Y>
```

## Как я прочитаю результат

| Исход | Что записываю | Что это значит для установки Kit |
|---|---|---|
| **обе** строки, два источника | `instructions` **преодолевает** `AGENTS.md` | есть **универсальный** механизм: Kit ставит `kilo.jsonc` + `.kilo/rules/`, `AGENTS.md` не трогает |
| **только** `ENTRY-FROM-AGENTS` | `instructions` **не** преодолевает `AGENTS.md` | универсального механизма нет: Kit обязан **сначала посмотреть**, есть ли `AGENTS.md` |
| только `ENTRY-FROM-RULES` | `instructions` **перекрывает** `AGENTS.md` | **опасный** исход: правила владельца молча выпадают; Kit обязан предупреждать и не делать так |

## Ловушки, которые я буду отсекать при чтении

1. **`read` вместо контекста.** Если агент начнёт «читать файл», чтобы ответить, — это не загрузка правил.
   Признак настоящей загрузки: в рассуждении есть строка `Instructions from: <путь>`.
2. **Догадка.** Если агент назовёт `ENTRY-FROM-RULES`, не сославшись на источник, — засчитаю как
   «не подтверждено», а не как «работает».
3. **Старый контекст.** Вопрос надо задать в **новом чате**: в старом уже лежит прежний системный промпт
   без `kilo.jsonc`, и разницы не будет видно.

## Зачем это вообще нужно

E25 показал: `.kilo/rules/` молча вытесняется любым `AGENTS.md`. У владельца чужого проекта `AGENTS.md`
почти всегда есть. Если `instructions` умеет это преодолевать — Kit ставится **одинаково** в любой проект.
Если нет — установщик обязан ветвиться, и это надо написать в инструкции прямым текстом, а не оставлять
на догадку.
