# Снимок реестров в памяти `.78a`

`research/audit/registry_backup_study.py` — опытный in-memory формат, **не законченная
резервная копия и не восстановление**. Захватывает точные bytes L0/L1/L2 и историю, которая
уже содержится внутри реестров, через штатный cooperative shared flock чтения. Незавершённый
move или стадия copy блокируют штатную загрузку. Захват и проверка требуют отдельно заданный
pin L0, валидную схему, корни, историю и каталог без конфликтов. Состояние чужих процессов,
файлов вне этих трёх реестров, кода Kit, иных профилей, метаданных и ACL не включается.

Проволочный формат: канонический ASCII JSON format 1, product, `profile_root`, `system_sha256`
и три записи `{bytes, sha256, base64}`. Декодирование ограничено, поля закрыты, повторы и
неправильный base64 отклоняются, повторно проверяются хеши, pin, schema, связи и журналы.
Не импортируется код из данных. С `.78b` размер каждого файла проверяется до ограниченного чтения относительно открытого
каталога; выполняются повторное чтение, проверка привязок директорий и pending-маркеров.
Это не исключает гонки некооперативных писателей. Самохеши не обеспечивают происхождение или защиту от умышленной замены;
тест показывает принятие изменённых с пересчитанным хешем валидных bytes.

API `capture` возвращает снимок в памяти и не создаёт файл. Содержимое может быть чувствительным;
криптографическая конфиденциальность, изоляция и авторизация отсутствуют. Нет подписи, переноса,
восстановления, UI или полного резервирования; Python/код и pin должны быть доверены заранее. Shared flock действует только на кооперативных писателей;
чтение файлов, TOCTOU, сетевые ФС и отказ питания не доказаны. Удалять или заменять данные
на основании результата нельзя.

Синтетические тесты проверяют точные bytes и журналы (включая отдельную ручную временную
копию), ошибочные pin/хеш/формат/base64, согласованно переписанную неверную историю и корень,
блокирующие стадии и возможность переподписать самохеши. Ручная копия в тесте не является
реализованным API восстановления; приёмка `.78`, G1–G6 остаётся открытой.

## Опытная публикация `.78c`

`registry_backup_publish_study.BackupSession` строит полный план нового каталога вне
источника с именем стадии, хешем и размером файла `backup.json`, а затем требует отдельное
подтверждение плана. Перед записью источник повторно читается и сверяется, цель не
перезаписывается; публикация через стадию, проверку bytes, fsync и Linux rename NOREPLACE.
Стадии с зарезервированным префиксом блокируют повторную публикацию в этот родитель;
при отказе после попытки rename — `publication_unknown`, ничего не удаляется автоматически.
Блокировка родителя и source flock только кооперативные, последовательность не является
атомарным снимком всей системы. Метки `fsync_calls_completed` не доказывают физическую
сохранность при отключении питания. Нельзя без отдельного расследования и плана удалять
стадию или повторять неизвестную операцию.

Файл **не зашифрован и не подписан**, может содержать секреты. Проба подтверждает лишь
точность трёх реестров/встроенной истории, не файлы проекта, код, права, provenance,
полноту или восстановимость. Никакой общей установки, шифрования, внешнего хранилища или
UI этот API не предоставляет. Применять только к временным синтетическим данным. Пробы
включают отмену, изменение исходного L1, занятую цель, ошибку fsync и rename; это не
физические отключения питания или независимая приёмка.
