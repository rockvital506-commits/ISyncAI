# Решение по роадмапу: применяю C сейчас + B после первой итерации

**Дата:** 2026-11-22 · **Статус:** рекомендация владельца подтверждена · **Не применено к файлам**

## 1. Что выбрано

| Шаг | Действие | Когда |
|---|---|---|
| 1 | Протокол `ROADMAP-PROTOCOL.md` вступает в силу для всех новых итераций | сейчас |
| 2 | `research/STRATEGY.md` **не переименовывается**, но объявляется роадмапом: разделы «Финал» и «Путь» | сейчас, документально |
| 3 | Отдельный файл `research/ROADMAP.md` создаётся как рабочая версия тела | при первой итерации, где тело реально меняется |
| 4 | Роадмап перестаёт быть членом печати | начиная с той же итерации, не задним числом |
| 5 | `STRATEGY.md` замораживается с пометкой «заменён роадмапом» | тогда же, одной строкой |

Причина выбора: любая правка байтов `STRATEGY.md` ломает печать И‑121 (проверено трижды: абзац —
`mismatch`, шапка 180 символов — `mismatch`, откат — `ok`). Значит переименование сейчас = пересборка
печати прошлой итерации ради косметики. Правильный момент — когда тело и так меняется по делу.

## 2. Что меняется с этого момента (без правки файлов)

1. В каждом замысле итерации фиксируются `roadmap_version` и `roadmap_sha256`.
2. Классификация правок: финал → MAJOR (только с «да»), маршрут → MINOR, формулировка → PATCH.
3. Правка тела после прогона — в том же коммите, с записью в журнал.
4. «Маршрут без изменений» — тоже запись, а не молчание.
5. Сомнение трактуется в сторону более высокого уровня изменения.

## 3. Структура целей на всех отрезках (по вашему требованию)

Каждая цель — на четырёх уровнях, и у каждой три состояния: **эталон**, **допустимое отклонение**,
**критическое отклонение**. Подробно — `TARGETS.md`. Кратко:

| Уровень | Цель | Эталон | Допустимо | Критично |
|---|---|---|---|---|
| **Итог (M3, 0.2.0)** | переносимая система: чужой агент инициализируется по документу, правила переносятся, нарушения ловятся без модели | все ворота M1–M3 пройдены и подтверждены печатями | часть Ф8 «условно пригоден» с явным списком `not run` | правило не переносится или нарушение не ловится |
| **Фаза** | одна поверхность, один доказуемый инвариант | 0 `fail`, 0 пропущенных обязательных, П3+П4 | `not run` перечислены и объяснены | пропущен обязательный шаг или критерий ослаблен после `fail` |
| **Итерация** | И‑122: старшинство Kilo по факту | 8 обязательных проб выполнены, 0 `fail`, RED→GREEN | часть проб `inconclusive` с объяснением, И‑122 остаётся открытой | выдуманное покрытие, `pass` без наблюдения |
| **Шаг/проба** | одна проба в одном состоянии | наблюдение записано дословно, уровень определён | «не понял» — законный результат | пробел выдан за результат |

## 4. Что это даёт при ветвлении сценариев

Сценарий выбирается по состоянию, а состояние — по отклонению:

```
наблюдение → сравнение с эталоном
   ├─ совпало              → сценарий штатный (SC-01…SC-09)
   ├─ допустимое отклонение → сценарий с поправкой, фиксируется в отчёте
   └─ критическое           → стоп, находка в GAPS, правка тела роадмапа (MINOR)
```

Это тот же алгоритм, что `spec_check.py --state`: сначала ошибки, потом пробелы, потом вывод.

## 5. Чего это решение не делает

- Не меняет ни одного байта `research/STRATEGY.md`.
- Не пересобирает печать И‑121.
- Не вводит обязательств сверх §7 роадмапа.
- Не отменяет P12, состав P0, порядок фаз и 40 итераций.
