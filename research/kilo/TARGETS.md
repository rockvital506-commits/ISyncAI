# Цели проекта: эталон, допустимые и критические отклонения

**Дата:** 2026-11-22 · **Основание:** требование владельца + `ROADMAP-PROTOCOL.md`
**Назначение:** единая шкала для синхронизации роадмапа и работы; вход для выбора сценариев и состояний.

## 0. Три определения на любом уровне

| Термин | Что означает | Кто решает |
|---|---|---|
| **Эталон** | проверяемое описание результата, при котором цель считается достигнутой | владелец (финал) / роадмап (маршрут) |
| **Допустимое отклонение** | результат хуже эталона, но цель остаётся достижимой; обязательна запись, что именно не сделано | агент, с записью в журнал |
| **Критическое отклонение** | результат, при котором цель **не** достигнута и продолжение по этому пути запрещено без решения владельца | только владелец снимает |

Правило: **допустимое отклонение нельзя накапливать молча.** Каждое попадает в отчёт списком.
Критическое — останавливает работу, а не «учитывается».

## 1. Итоговая цель (M3, выпуск 0.2.0)

### 1.1 Формулировка

Переносимая и поддерживаемая система контрактов, которой управляет обычная фраза пользователя, и
которая не зависит от автора: новый владелец и посторонний агент начинают работу по документу.

### 1.2 Что должно работать в итоге (функционал)

| # | Возможность | Чем подтверждается |
|---|---|---|
| Ф1 | Инициализация без калибровки: `install`/`connect` + `create` | И‑112 и пилот И‑134/135 |
| Ф2 | Карточка операции из обычной фразы, `missing[]`, ≤3 вопроса | И‑108, И‑111 |
| Ф3 | План с точным диффом и билетом; запись только по подтверждению | И‑109, И‑110 |
| Ф4 | Три области L0/L1/L2 с разными правами; L0 неизменяем | И‑104–107 |
| Ф5 | Перенос L2→L1, имитация, просмотр конфликтов | И‑114–116 |
| Ф6 | Пакет, проверка целостности, доверие, откат N‑1 | И‑117–120 |
| Ф7 | Принуждение без модели: `guard` локально и в CI | И‑127, И‑128 |
| Ф8 | Адаптеры трёх сред с измеренным `read_rate` | И‑121–126, 134–137 |
| Ф9 | Сопровождение: обновление, миграция 0.1.36→0.2.0, восстановление | И‑130–133 |
| Ф10 | Релиз: README, INIT‑PROMPT, протокол, «первые 10 минут» | И‑138–140 |

### 1.3 Эталон

- Все ворота M1 (И‑127), M2 (И‑118), M3 (И‑140) пройдены и подтверждены печатями.
- У каждой среды есть вердикт пригодности с **числом прогонов** (И‑137), а не «работает».
- Любое утверждение в отчётах имеет `basis` и `criterion`.

### 1.4 Допустимые отклонения

| Отклонение | Условие допустимости | Как фиксируется |
|---|---|---|
| Часть сред остаётся `not run` | среды физически недоступны, и это записано | список `not run` в вердикте И‑137 |
| Вердикт «условно пригоден» | ограничения названы, риск принят владельцем | строка вердикта + ограничения |
| Миграция неполная | правила сохранены, потери перечислены | отчёт И‑131 с диффом |

### 1.5 Критические отклонения

- Правило Kit теряется или молча перезаписывается при миграции.
- Нарушение не ловится без участия модели там, где это обещано.
- Итог объявлен достигнутым при открытых дефектах P0.
- «Работает» сказано без числа прогонов и без среды.

## 2. Фазовая цель (на примере Ф5, текущая)

### 2.1 Эталон

- Каждая из трёх сред: явный `status` и перечисленные пробелы покрытия.
- У каждой среды известно старшинство входов **по факту**, а не по документации.
- Заглушки имеют причину и не выдают себя за рабочие.

### 2.2 Допустимые отклонения

- `status: candidate` с честным списком `not run`.
- Старшинство известно для одной среды и одного режима (P12), для остальных — `not run`.
- Матрица заполнена частично, но без выдуманных чисел.

### 2.3 Критические отклонения

- Снятая заглушка без прогона.
- `documented` или `empirical` без наблюдения.
- Доли `read_rate`/`apply_rate`, полученные не измерением.

## 3. Целевая итерация (И‑122, Kilo)

### 3.1 Эталон

- Восемь обязательных проб выполнены в согласованной среде с записью версий.
- RED до правки, GREEN после, 0 `fail`, 0 пропущенных обязательных.
- Отчёт с `basis`/`criterion`, печать, страница, запись сверки — по общему протоколу.
- Точка входа подтверждена **наблюдением**, а не документацией: каталог `.kilo/rules/` подхватывается
  без `kilo.jsonc` (П1), `instructions` не обязателен и не дублирует (П2).
- Старшинство `AGENTS.md` против `instructions` — подтверждено для случая **чтения** (П3);
  для случая **конфликта значений** остаётся открытым (`E25`).

### 3.2 Допустимые отклонения

| Отклонение | Условие | Фиксация |
|---|---|---|
| Провайдер недоступен | сеанс не стартует; записывается как блокер `E16` | отчёт, И‑122 остаётся открытой |
| Часть проб `inconclusive` | причина названа, проба не засчитана | список в приёмке |
| Только одна версия расширения | P12 соблюдён | `not run` для остальных версий |
| Одна бесплатная модель (`Auto Free`) | модель выбрана маршрутизатором, недоступна фиксация | `D-PROVIDER`, отметка в каждой карточке |
| Модель маршрутизируется и меняется между сессиями | окно и поведение сверяются по счётчику перед пробой | расхождение токенов фиксируется (`E33`) |

### 3.3 Критические отклонения

- Проба засчитана без наблюдения.
- Ответ агента принят за доказательство чтения без цитаты или признака.
- Изменён критерий после `fail`.
- Заявлено «Kilo читает AGENTS.md», если не было ни обнаружения, ни чтения.
- Заявлено «Kit не сломает чужой проект» **без внешнего контроля** (хеши до/после): П3 показал, что
  `AGENTS.md` не защищён от записи и текст внутри файла не ограничивает агента.
- Заявлено «секреты не утекут» на основании `permission`: П7 показал, что `deny read *.env` обходится
  через `bash`.
- Критерий «указать `instructions`» используется как обязательный: П1/П2 показали, что достаточно
  каталога `.kilo/rules/`.
- Результат проб обобщён на «Kilo вообще», хотя получен на одной модели `Auto Free` (см. §3.4).

### 3.4 Ограничение, вытекающее из бесплатного тарифа (2026-11-24)

Владелец использует бесплатный доступ: провайдер не подключён, модель — `Auto Free` (`kilo-auto/free`).
Это **маршрутизатор**, а не одна модель (S23, S24): состав и окна меняются, окна у бесплатных моделей
различаются от 32K до 1M (S25). Отсюда три правила для приёмки:

| Правило | Почему |
|---|---|
| Окно контекста фиксируется **по счётчику интерфейса** в начале каждой сессии | ответ модели недостоверен (П8: 200K вместо 256K) |
| Результаты проб привязаны к дате и модели; перенос на другие модели — `not run` | модель ≠ поверхность продукта, но и не константа |
| В free-тариф не передаются данные, которые нельзя отдавать в обучение | S24: free-модели могут маршрутизироваться к провайдерам, обучающимся на промптах |

## 4. Уровень шага и пробы

| | Определение |
|---|---|
| **Эталон** | наблюдение записано дословно: что сделал, что видно, чего не было |
| **Допустимо** | «не понял, что произошло», «не воспроизведено» — при условии, что это записано как есть |
| **Критично** | пустая строка вместо наблюдения; объединение «не видел» и «не работает» |

## 5. Как это связано со сценариями и состояниями

| Отклонение | Что происходит со сценарием | Что происходит с состоянием |
|---|---|---|
| эталон | штатный сценарий `SC-*` | состояние `ST-*` берётся как есть |
| допустимое | сценарий выполняется с поправкой, поправка в отчёте | состояние дополняется, пробел остаётся в `GAPS` |
| критическое | сценарий **не** выполняется | состояние помечается `blocked`, нужна правка роадмапа |

Это же основание для `spec_check.py`: `error` = критично, `gap` = допустимо, `info` = эталон.

## 6. Что нужно, чтобы шкала заработала

1. Пороги для каждого уровня — решение владельца, не агента. Сейчас они заданы качественно.
2. Числовые пороги (сколько `not run` ещё допустимо) появятся после И‑125, где есть N.
3. Изменение любого эталона — MAJOR, только с подтверждением.
