## Часть 1. Ориентир → роадмап: варианты

Общая цель всех вариантов: сделать **тело** роадмапа изменяемым, не переписывая историю принятых
итераций, и сохранить финал под контролем владельца.

### A · Переименовать и вынести (полная миграция)

Переименовать `research/STRATEGY.md` → `research/ROADMAP.md`, разделить на «Финал» и «Путь»,
`research/strategy/SYNC-LOG.md` → журнал роадмапа. Убрать файл из членов печати.

| | |
|---|---|
| **Даёт** | смысл совпадает с именем; тело свободно меняется, версия и хеш фиксируются |
| **Цена** | ломает `research/121` (26 членов печати, 9 исторических пинов, `ITERATION.json`, аттестации). Требует перепечати И‑121 или явной амнистии |
| **Риск** | «переписывание прошлого» — ровно то, что запрещает протокол |
| **Когда выбирать** | если вы готовы один раз принять пересборку И‑121 и забыть про это навсегда |

### B · Добавить роадмап рядом, старый оставить (аддитивно)

Создать `research/ROADMAP.md` как рабочую версию, а `STRATEGY.md` заморозить как исторический
документ (v1.23, «не меняется»).

| | |
|---|---|
| **Даёт** | печати целы; ничего не переписывается; новый документ сразу с правильными правами |
| **Цена** | два документа; нужен явный порядок «что главнее», иначе появится два источника истины |
| **Риск** | расхождение между ними; «а в старом написано иначе» |
| **Когда выбирать** | если приоритет — не трогать историю и быстро начать работать по новому |

### C · Не переименовывать, сменить только роль (минимально)

Оставить `STRATEGY.md`, но объявить его роадмапом: раздел «Финал»/«Путь», правило «не член печати
со следующей итерации», протокол `ROADMAP-PROTOCOL.md` применяется начиная с И‑122.

| | |
|---|---|
| **Даёт** | ноль переименований, ноль перепечатей; протокол действует с завтрашнего дня |
| **Цена** | имя файла не отражает смысл — вы просили переименовать |
| **Риск** | путаница «это стратегия или роадмап» |
| **Когда выбирать** | если имя не критично, а важна дешевизна |

### D · Переименовать, но печать И‑121 оставить как есть (с амнистией)

Переименовать файл, а в записи И‑121 добавить строку: «члены печати сверяются по снимку коммита
`9ef5a6d`; переименование роадмапа не является изменением предмета итерации».

| | |
|---|---|
| **Даёт** | смысл + тело свободно + история не переписана |
| **Цена** | нужна правка `research/121` (документальная, не код); формально меняет артефакт итерации |
| **Риск** | «амнистия» как привычка — тогда печати перестают что-либо значить |
| **Когда выбирать** | если хотите и имя, и целую историю, и принимаете одну документальную правку |

### Моя рекомендация

**B**, с оговоркой: в `STRATEGY.md` добавляется одна строка «заменён роадмапом, не меняется», и
именно она требует пересборки. Поэтому на практике дешевле **C сейчас, B сразу после** первой
итерации, где роадмап и так меняется (там пересборка происходит по делу, а не ради переименования).

Если имя важно прямо сейчас — **D**: одна документальная правка вместо переписывания.

## Часть 2. Публикация досье

Вы сказали: публиковать. Уточнение, которое я обязан назвать, потому что оно меняет смысл:

> Публикация — это **commit + push** в `arena/4e000a5e-isyncai`. Это изменяет `origin` и
> потенциально влияет на другие сессии, которые на него смотрят.

Мой план (по образцу И‑121, но без новой печати):

1. Явный список всех файлов `research/kilo/` — 26 путей, без «добавить всё».
2. Проверка: нет секретов, нет `.env`, нет ключей, нет рабочих данных (скрины не копируются в git —
   сохраняются только разборы).
3. `git add` только этих путей, `git diff --cached --check`, сверка числа файлов.
4. Один коммит: `research/kilo: досье среды Kilo Code (данные, состояния, сценарии, протокол роадмапа)`.
5. Обычный push в текущую ветку, сверка `origin` = `HEAD`.
6. Проверка, что `research/121` не тронут и `--verify-seal` по-прежнему `ok`.

**Чего я не буду делать без отдельного согласия:** трогать `.gitignore`, добавлять теги, делать PR,
менять другие ветки, переписывать историю.
