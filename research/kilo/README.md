## 1. Чем это не является

- **Не второй реестр Kit.** Здесь нет правил Kit, их копий или альтернативной записи профиля.
  Только сведения о среде исполнения: что она читает, в каком порядке и с какими правами.
- **Не доказательство поведения.** Ни одна строка ниже не является наблюдением. Максимум —
  «так описано в документации версии X».
- **Не замена действующего роадмапа.** В момент составления досья действовала стратегия
  v1.23; теперь приоритет уточнений владельца указан в `ROADMAP.md`. Исторические критерии
  И‑122, её материалы и печать этим досье не меняются.
- **Не адаптер и не установка.** Расширения не устанавливались, клиенты не запускались,
  глобальные настройки не читались и не менялись.

## 2. Уровни свидетельства (единая шкала)

| Код | Что означает | Что позволяет утверждать |
|---|---|---|
| `vendor` | официальная документация или реестр Kilo той же версии | «описано так» о документации, не о поведении |
| `secondary` | обзоры, гайды, пересказы документации третьими лицами | только гипотеза для проверки |
| `observed_ui` | скриншот интерфейса пользователя с датой и версией | «в UI видно так»; настройки и версия, не поведение |
| `observed` | собственный прогон в названной версии, режиме и состоянии | «ведёт себя так» в этом состоянии |
| `not run` | данных нет | ничего; пустое значение не равно нулю |

`observed_ui` — отдельный уровень: он сильнее документации по настройкам и слабее прогона по
поведению. Скриншот не доказывает чтение файлов проекта.

Правило: **число, взятое из `vendor`, не переносится в отчёт как измеренное.** Ранг 3 из 4,
доли чтения и лимиты контекста остаются `not run`, пока нет `observed`.

## 3. Файлы и порядок чтения

```
каталог (этот README)
   → выборка: STATES.json (какое состояние воспроизводим) + SCENARIOS.json (какой сценарий)
       → тело: ENTITIES.json (что за настройка, значения, связи, эффект)
                SOURCES.json (чем подтверждено и с какой надёжностью)
                   GAPS.md (что противоречит и что надо измерить)
```

| Вопрос | Файл | Поле |
|---|---|---|
| Какие источники инструкций знает Kilo и в каком порядке? | `ENTITIES.json` | `priority` у `ENT-*` |
| Какое состояние среды нужно для сценария? | `STATES.json` | `fingerprint`, `expected` |
| Чем это подтверждено и насколько надёжно? | `SOURCES.json` | `kind`, `reliability` |
| Что противоречит друг другу? | `GAPS.md` | `C*` |
| Как это измерить в И‑122? | `GAPS.md` | `E*` |

Это тот же принцип, что P8: сначала дешёвый каталог, затем узкая выборка, и только потом полное
тело. Полные тексты документации здесь не копируются — хранится утверждение, ссылка и дата.

## 4. Как выбирать состояние под сценарий (фильтры ветвления)

Три фильтра, в этом порядке:

- **Ф1 · версия и канал.** Текущее расширение v7 построено на Kilo CLI; расширение 4.x/6.x —
  прежняя архитектура с `.kilocodemodes`. Поведение между ними не переносится.
- **Ф2 · источник входа.** `agent.<name>.prompt` → `instructions` (проект) → `AGENTS.md` →
  `instructions` (глобально) → skills по требованию. Разные источники — разные сценарии.
- **Ф3 · права.** `allow` / `ask` / `deny`, glob, последнее совпадение выигрывает, при отсутствии
  правила — `ask`. Права ограничивают действие, но не доказывают, что инструкция прочитана.

Если фильтр не определён — сценарий не выбирается, а помечается `not run`. Угадывание версии или
режима запрещено: это подмена состояния.

## 5. Правила пополнения

1. Каждая запись несёт `checked` (дата), `kind` и ссылку. Без даты запись не добавляется.
2. Противоречия не сглаживаются: обе версии остаются, расхождение уходит в `GAPS.md`.
3. Числа версии не переносятся между версиями и каналами (stable/pre-release).
4. Скриншот пользователя — `observed` **только** для того, что на нём видно: имя версии, список
   агентов, значения переключателей. Намерение и фактическое чтение файлов из скрина не следуют.
5. Каждое утверждение получает `basis` (источник) и `criterion` (как проверить) по P11.

## 6. Что из этого досье нельзя брать в И‑122

- «ранг 3 из 4» — как факт о поведении (это описание документации);
- «работает» / «подключено» — без прогона;
- любые доли, капы и лимиты контекста — до И‑125/И‑126;
- совпадение названий файлов с ожиданием Kit — как доказательство чтения (P13).

Досье даёт **список гипотез и точку их проверки**, а не результат.

сводка — `PROBES-RESULT-2026-11-24.md`. Коротко:

- **Что это значит:** обещание «Kit не сломает чужой проект» держится на внешнем контроле (хеши, откат),
  а не на правилах Kilo. Защита секретов средствами агента не гарантируется — гарантируется видимость.
