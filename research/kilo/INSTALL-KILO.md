# Установка Kit в проект под Kilo: измеренный рецепт

**Для кого:** владелец проекта, который ставит Kit в **свой** проект с Kilo Code.
**На чём основано:** 12 проб на Kilo 7.8.32 / VS Code 1.147.0 / `Auto Free`, 2026‑11‑24.
Каждый шаг ниже **наблюдался**, а не взят из документации. Ссылка на карточку — в конце строки.
**Чего в документе нет:** обещаний, которые пробы опровергли (список — §7).

## 0. Что понадобится

| Нужно | Зачем | Проверка |
|---|---|---|
| Kilo Code 7.8.32 или новее | на 7.8.32 поведение измерено | шестерёнка → «О Kilo Code» → Версия |
| Проект открыт в VS Code целиком | `kilo.jsonc` читается при открытии папки | заголовок окна = имя проекта |
| 10 минут | 5 шагов + проверка | — |

**Про бесплатную модель.** Kit работает и на `Auto Free`: пробы это подтвердили. Ограничения free‑тарифа
описаны в §6 — прочитайте их **до** установки, если в проекте есть данные, которые нельзя отдавать
в обучение моделей.

## 1. Шаг 1 — выключить автоодобрение

**Действие.** В панели чата Kilo нажмите кнопку‑**щит** так, чтобы подсказка стала
«Автодобрение **отключено**».

**Зачем.** При включённом щите подтверждения не спрашиваются, и действие агента выглядит как «Одобрено
вами», хотя вас не спрашивали. В этом состоянии установка непроверяема и всё, что делает агент, проходит
молча. *(П3, E27)*

**Проверка.** Наведите курсор на щит: текст должен содержать «Автодобрение отключено».

## 2. Шаг 2 — создать `kilo.jsonc` в корне проекта

**Файл** — `kilo.jsonc` рядом с папками проекта (не внутри `.kilo/`):

```jsonc
{
  "$schema": "https://app.kilo.ai/config.json",
  "instructions": [".kilo/rules/*.md"]
}
```

**Зачем именно так.** Без этой строки Kilo подхватывает `.kilo/rules/` **только пока в проекте нет
`AGENTS.md`**. Если `AGENTS.md` есть — каталог молча игнорируется, и правила не работают без единой
ошибки на экране. С этой строкой каталог грузится **всегда**. *(E25 — без неё; E36 — с ней)*

**Проверка.** Файл сохранён, в заголовке вкладки нет точки (несохранённых изменений нет).

## 3. Шаг 3 — положить правила в `.kilo/rules/`

**Действие.** Создайте папку `.kilo\rules\` и положите туда файл `.md` с правилами Kit.
Один файл — одна тема; имя латиницей, без пробелов.

**Зачем.** Это каталог, который читается автоматически и не требует правки чужих файлов. *(П1)*

**Чего НЕ делать.** Не добавляйте правила в `AGENTS.md` владельца проекта. В него **не нужно** писать:
`kilo.jsonc` решает задачу без этого. А изменить его агент может, и текст‑запрет внутри файла его не
остановит. *(E36 — не требуется; П3 — не защищён)*

**Проверка.** Файл на месте, кодировка UTF‑8 (BOM допустим — проверено).

## 4. Шаг 4 — перезагрузить окно

**Действие.** `Ctrl+Shift+P` → `Developer: Reload Window`.

**Зачем.** Проектный `kilo.jsonc` читается при открытии проекта; без перезагрузки он не подхватится.

**Дальше** правки правил перезагрузки **не требуют**: достаточно `Ctrl+Shift+P` →
`Kilo: Reload Config and Skills`. Изменение применяется в текущей сессии. *(П6)*

## 5. Шаг 5 — доказать, что правило работает

**Действие.** Новый чат (кнопка `+`). Отправьте:

```
Не читая файлов, повтори дословно одну строку из правил Kit. Если такой строки в контексте нет —
ответь ровно: НЕТ В КОНТЕКСТЕ
```

**Что считать успехом.** Агент процитировал строку **и** в блоке рассуждения есть
`Instructions from: <путь к вашему файлу>`.

**Что считать провалом.** Ответ `НЕТ В КОНТЕКСТЕ`, или строка найдена «чтением файла» (без
`Instructions from:`) — это не загрузка правил, а поиск.

**Если провал** — вернитесь к шагу 2 и проверьте путь в `instructions` (glob должен совпадать с
реальным именем файла). *(П1)*

## 6. Ограничения, которые надо знать заранее

| Ограничение | Что это значит на практике |
|---|---|
| **Бесплатная модель — маршрутизатор** | модель может меняться от сессии к сессии; окно контекста тоже. Смотрите счётчик `X / Y` в шапке чата при каждом старте *(П8, S24)* |
| **Free‑тариф может обучаться на запросах** | по документации провайдера запросы на бесплатных моделях могут попадать в обучение. Не загружайте в такой проект данные, которые нельзя отдавать *(S24)* |
| **Окно контекста ограничено** | «каркас» Kilo занимает ≈16–18K токенов до ваших правил; файл правил добавляет ≈5K. Держите правила короткими *(П1, П8)* |
| **Агент не знает свой бюджет** | он называет окно неточно. Верьте **только** счётчику, не ответам модели *(П8)* |

## 7. Что вам НЕ обещают (проверено и опровергнуто)

Это самый важный раздел. Ниже — фразы, которые **нельзя** считать правдой про Kit в Kilo:

| Неверное ожидание | Что на самом деле |
|---|---|
| «Правила не дадут агенту изменить мой проект» | Может изменить. Правила ограничивают **инструменты агента**, но `deny` на запись обходится делегированием: агент вызывает субагента, и тот пишет *(E27)* |
| «Секреты защищены: агент не прочитает `.env`» | Прочитает. Запрет на инструмент `read` обходится через `bash`: тот же файл, другая команда *(П7)* |
| «Агент только на чтение» | Пока не делегирует. У субагента свои права *(E27)* |
| «Достаточно настроить права» | `ask` работает только при выключенном щите. Включённый щит превращает `ask` в молчаливое согласие *(П3, П5, П7)* |
| «`AGENTS.md` защищён от изменения» | Не защищён. Агент прочитал запрет внутри файла и изменил его, сославшись на вашу просьбу *(П3)* |

## 8. Настоящая защита: три вещи, а не настройка

| Что | Как | Почему это работает |
|---|---|---|
| **1. Щит выключен** | шаг 1 | каждое действие показывает окно подтверждения: вы видите, что агент собирается сделать |
| **2. Сверка хешей** | до и после работы: `Get-FileHash <файл> -Algorithm SHA256` | изменение видно даже если агент «сказал, что не менял» |
| **3. Откат** | git или копия файла до работы | любое изменение можно вернуть |

**Формулировка, которой можно пользоваться при объяснении:**

> Правила Kit задают, **как** агент работает. Защиту обеспечивает **выключенный щит и сверка файлов**,
> а не правила.

## 9. Если что‑то не работает

| Симптом | Причина | Что делать |
|---|---|---|
| `НЕТ В КОНТЕКСТЕ` на шаге 5 | нет `kilo.jsonc` или путь в `instructions` не совпадает | шаг 2, проверить glob |
| правило видно, но агент его не соблюдает | правило прочитано, но не применено — это разные вещи | переформулировать как действие («не делай X»), а не как описание |
| правило «иногда работает» | в контексте одновременно `AGENTS.md` и `.kilo/rules/` с разными указаниями | убрать противоречие: не дублировать правила в `AGENTS.md` |
| запросы подтверждения не появляются | включён щит | шаг 1 |
| `ls -la` в чате падает с ошибкой PowerShell | инструмент называется `bash`, но исполняет PowerShell | использовать синтаксис PowerShell *(C24)* |

## 10. Что делать дальше

- Правка правил: `Kilo: Reload Config and Skills`, новый чат для проверки.
- Перед работой с важными файлами: `Get-FileHash` до и после, показать разницу.
- Если проект чужой: **не** правьте его `AGENTS.md`; используйте `kilo.jsonc` + `.kilo/rules/`.
