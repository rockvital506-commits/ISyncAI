# Протокол работы с файлом роадмапа (ранее «ориентир»)

**Дата:** 2026-11-22 · **Статус:** предложение, не применено · **Не итерация**
**Основание:** уточнение владельца + эмпирическая находка (правка `STRATEGY.md` ломает печать И‑121)

## 1. Определения

**Роадмап** — единственный документ, задающий путь от текущего состояния к конечным целям проекта.
Три части с разными правами:

| Часть | Что содержит | Кто меняет | Как часто |
|---|---|---|---|
| **Финал** | конечные цели, определение «пригоден», инварианты A1–A4, состав P0, порядок фаз, вехи | **только владелец**, явным подтверждением | почти никогда |
| **Тело пути** | фазы, итерации, что доказывает каждая, критерии, допущения Д1–Д7, анти-скоуп | агент по §7 при проверяемом основании | каждую итерацию, если есть основание |
| **Журнал** | записи сверок: факт, опровергнутое, правка, версия | агент вместе с правкой | всегда |

**Версия роадмапа** — не версия продукта. Три уровня:
- **MAJOR** — изменился финал. Только с подтверждением владельца. Молча запрещено.
- **MINOR** — изменился маршрут: добавлена/убрана/переупорядочена итерация, изменён способ
  доказательства.
- **PATCH** — изменилась формулировка без смены смысла, критериев и порядка.

**Снимок роадмапа** — пара `(версия, SHA‑256)`. Именно она попадает в артефакты итерации.

## 2. Найденная проблема (почему это не косметика)

Проверено 2026-11-22:

1. `research/STRATEGY.md` входит в **26 членов печати И‑121**.
2. Замена одного абзаца изменила сборку: `rebuilt_sha256` другой, `--verify-seal` → `mismatch`.
3. Откат вернул `ok`.

**Вывод:** пока роадмап лежит **внутри** печати, он фактически неизменяем. Но по смыслу его тело
должно быть мутабельным. Это противоречие архитектуры, а не ошибка исполнения.

**Правило, которое из этого следует:**

> Роадмап **не входит** в члены печати итерации. Итерация фиксирует **хеш роадмапа, против
> которого она выполнена**. Печать подтверждает артефакты итерации, а не актуальность маршрута.

Так прошлые печати остаются проверяемыми при любых будущих правках маршрута — иначе каждая правка
роадмапа переписывала бы историю.

## 3. Что можно и чего нельзя

| Действие | Можно | Нельзя |
|---|---|---|
| Изменить конечную цель | только с явным «да» владельца + MAJOR | «по ходу стало ясно» |
| Переупорядочить итерации | по §7.3, с записью и подтверждением | молча, «чтобы удобнее» |
| Уточнить формулировку критерия | PATCH, с записью | ослабить критерий после `fail` |
| Добавить итерацию | MINOR, с записью и обоснованием | добавить «на всякий случай» |
| Удалить итерацию | §7.4: назвать, какой инвариант где доказывается вместо неё | удалить без замены |
| Поправить после прогона | обязательно, в том же коммите | оставить расхождение незаписанным |

## 4. Протокол «до итерации» (П0‑Р)

1. Прочитать **финал** и **тело** — только нужную фазу, не весь файл (бюджет P8).
2. Зафиксировать `roadmap_version` и `roadmap_sha256` в замысле итерации.
3. Сверить **факт с описанием фазы**: что план утверждает и что известно на самом деле.
4. Если расхождение — классифицировать:
   - изменился финал → **стоп**, вопрос владельцу;
   - изменился маршрут → правка вносится **до** работы, чтобы не доказывать по старому пути;
   - только формулировка → PATCH, запись.
5. Записать в замысел одну из двух строк: «маршрут действует без изменений» или «предложена
   правка X, основание Y».
6. Начать работу можно только после того, как маршрут однозначен.

## 5. Протокол «после итерации» (П9‑Р)

1. Сверить: что подтвердилось, что опровергнуто, что осталось `not run`.
2. При опровержении — правка тела по §7 и повышение версии (MINOR/PATCH).
3. Запись в журнал: номер, факт, опровергнутое, правка, новая версия.
4. Обновить `roadmap_sha256` в артефактах итерации.
5. Проверить, что **печать итерации цела** (роадмап вне её членов).
6. Даже если менять нечего — записать «маршрут без изменений». Отсутствие записи не равно
   «не проверяли».

## 6. Алгоритм классификации изменения

Решается по проверяемому признаку, а не по ощущению:

```
Изменение затрагивает:
  ├─ конечные цели / «пригоден» / A1–A4 / состав P0 / порядок фаз / вехи → MAJOR (нужно «да»)
  ├─ перечень итераций / что доказывает итерация / способ проверки     → MINOR
  ├─ формулировки без смены смысла и критериев                          → PATCH
  └─ не уверен                                                          → MAJOR (консервативно)
```

Правило безопасности: **сомнение трактуется в сторону более высокого уровня**. Ошибка в сторону
«спросить» дешевле ошибки в сторону «молча поменял цель».

## 7. Как это ложится на текущие файлы

Сегодня роадмап — это `research/STRATEGY.md` (v1.23). Правка любого его байта ломает печать И‑121.
Возможные пути перехода — в `DECISION-ROADMAP.md` (варианты A–D с ценой).

Общее для всех вариантов:
- финал и тело разделяются явными разделами;
- каждая итерация пишет `roadmap_version` + `roadmap_sha256`;
- роадмап перестаёт быть членом печати — начиная со следующей итерации, не задним числом.

## 8. Анти-паттерны

| Анти-паттерн | Почему плохо |
|---|---|
| «Поправлю критерий, потому что тест не прошёл» | ошибка исполнения лечится правкой кода, а не критерия |
| «Поменяю цель, это же логичнее» | финал меняет только владелец |
| Две правки без записи в журнал | теряется основание, версия врёт |
| Роадмап внутри печати | любая правка переписывает историю |
| «Маршрут не менялся» без записи | нельзя отличить «проверили» от «забыли» |
| Снимок версии без хеша | версию можно переписать, хеш — нет |

(а историческую оставить как есть), дальнейшие правки перестанут ломать сверку. Цена — одна
перепечать, зато навсегда.

## 11. Шкала отклонений на каждом уровне (требование владельца)

Для **любой** цели — итоговой, фазовой, итеративной, шаговой — определяются три состояния:
**эталон**, **допустимое отклонение**, **критическое отклонение**. Полные определения и таблицы
по уровням — `TARGETS.md`.

Правила, которые из этого следуют:

1. Эталон формулируется **до** работы, вместе с критерием проверки.
2. Допустимое отклонение записывается в отчёт списком; молча накапливать нельзя.
3. Критическое отклонение останавливает работу и требует решения владельца — не «учитывается».
4. Совпадение с эталоном тоже записывается: «отклонений нет» — это утверждение, а не тишина.
5. Шкала совпадает с уровнями `spec_check.py`: `error` — критично, `gap` — допустимо, `info` — эталон.
6. Это вход для ветвления: эталон → штатный сценарий; допустимое → сценарий с поправкой;
   критичное → сценарий не выполняется.
