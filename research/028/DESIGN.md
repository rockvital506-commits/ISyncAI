# И‑028 · Две среды на одном проекте: Kilo и Copilot поочерёдно — замысел до прогона

18 ноября 2026. Правило тождества не меняется. Адаптеры остальных сред (Claude Code, Cursor,
Antigravity) остаются **заглушками**: имя объявлено, обещаний нет. Предмет итерации — то, что до сих
пор не проверялось: **два расширения в одном открытом проекте**, которые обращаются к комплекту
по очереди.

## Сценарий, который проверяется

Проект открыт в VS Code. В нём включены оба расширения — Kilo Code и GitHub Copilot. Человек задаёт
задачу то одному, то другому; каждое расширение читает инструкции проекта, а комплект ведёт один вход
`AGENTS.md` и один реестр.

| Ход | Что делает среда | Что ожидается от комплекта |
|---|---|---|
| Kilo | читает `AGENTS.md`, пишет наблюдение | запись появляется один раз, вход не меняется |
| Copilot | читает тот же `AGENTS.md`, пишет то же наблюдение | новой записи нет, если среда не различается |
| Kilo | пишет другое наблюдение | новая запись |
| Copilot | создаёт правило | запись правила |
| Kilo | создаёт противоположное правило | отказ `conflict`, ничья не решается «кто позже» |
| любая | правит `AGENTS.md` вне контракта | `status` → `attention`, `update` → `adapter_drift` |

## Что известно про среды (сверено 18.11.2026, карточки 0.1.8)

| Свойство | Kilo | Copilot |
|---|---|---|
| вход комплекта | `AGENTS.md`, совпадает с входом среды | `AGENTS.md`, вход среды — `.github/copilot-instructions.md` |
| старшинство нашего входа | 3 из 4 | 4 из 5 |
| чужие наборы выше нашего | промпт агента, `instructions` в `kilo.jsonc` | личные, path-specific, общий файл |
| что комплект не пишет | `.kilo/`, `.kilocode/`, `kilo.jsonc` | `.github/`, `.vscode/`, `CLAUDE.md`, `GEMINI.md` |
| что не проверено | загрузка в редакторе, поведение с моделью | то же + Chat на github.com, inline suggestions |

## Ожидания, зафиксированные до прогона

`EXPECTATIONS.json` (15 пунктов) записан до первого запуска стенда. Коротко:

| Что | Ожидание |
|---|---|
| Испытания комплекта | 47 pass / 0 fail / 3 not run, обе линии (было 46) |
| Один вход на две среды | `AGENTS.md` один, его отпечаток не меняется между ходами |
| Настройки сред | ни одного изменённого байта в `.kilo/`, `.kilo/kilo.jsonc`, `.vscode/settings.json`, `.github/` |
| Тождество при одинаковом `environment` | повтор от второй среды не создаёт записи |
| Тождество при разном `extension` | две записи: `environment` сравнивается точно |
| Конфликт правил | отказ `conflict` в обе стороны |
| Порядок сред | не влияет на счётчики и на `rules.json` |
| Второй вход | `second_entry` даже в уже подключённом проекте |
| Чужая правка входа | `attention` и `adapter_drift`, вход не перезаписан |
| Заглушки | `status: stub`, нет входа и покрытия, `ack_existing` не отменяют |
| Повторный проход | `checks.json` не меняется ни на байт |

## Что будет означать провал

- настройки расширений изменены хотя бы на байт;
- появился второй вход или второй реестр;
- поведение зависит от того, какая среда ходила первой;
- заглушка заявляет факты, покрытие или старшинство;
- правило тождества поехало (корпус 24, журналы 3 из 3).

## Границы

Расширения не запускаются: «открытый в VS Code проект» — это раскладка файлов (`.vscode/settings.json`,
`.kilo/kilo.jsonc`, `.kilo/rules/…`) и вызовы команд комплекта от имени среды. Что именно каждая среда
передаёт модели, здесь не проверяется: это уровни достоверности 2–4 и живые модели. Windows, права и
журналы заказчика — `not run`.
