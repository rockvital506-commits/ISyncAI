# И‑056 · README-вектор и трассировка — замысел до прогона

18 ноября 2026. Выпуск **0.1.36**. Пятая и последняя итерация фазы «пригодность Kit к применению».

## В чём трудность

README к 0.1.35 вырос до **34 530 байт** и стал журналом: тридцать четыре раздела «Что изменилось в 0.1.N»
плюс вводные абзацы 0.1.0. Читать это как памятку нельзя — история выпусков уже есть в `releases/*/PROTOCOL.md`
и в `PROTOCOL.md`. При этом «максимально подробно» было понято как «максимально длинно», и ни одно утверждение
README не проверялось: разошлось с `START.md` — никто не заметил.

| Что | До 0.1.36 | Чем плохо |
|---|---|---|
| объём README | 34 530 B | памятку не читают и не перечитывают |
| назначение | журнал выпусков | история живёт в двух местах и расходится |
| проверяемость утверждений | нет | README мог обещать больше, чем есть |
| трассировка §2–§18 | нет | нельзя ответить «где доказательство этого пункта» |
| раздел «Чего нет» | нет | `not run` жил только в отчётах автора |

## Что появляется в продукте

- `README.md` переписан как **вектор смысла**: три входа (пользователь / агент / проверяющий), границы,
  смыслы файлов, команды, «Чего нет»; ≤ **24 КБ**;
- **якоря**: каждое утверждение заканчивается ссылкой `[START: фраза]`, `[PROTOCOL: фраза]`, `[INIT: фраза]`,
  `[КАЛИБРОВКА: фраза]`, `[X84]`, `[K2]`, `[manifest]`, `[TRACE]`;
- `TRACEABILITY.json` — §2…§18 → тема → артефакты → испытания → уровни → `covered`;
- `X87` (лимит, якоря разрешаются, утверждений без якоря нет), `X88` (§2…§18 покрыты, артефакты и испытания
  существуют), `X89` («Чего нет» = фактический список `not run`);
- сборка падает, если якорь ведёт в никуда, если раздел не покрыт, если список `not run` в README
  разошёлся с `reports/CHECKS.json`;
- уровень обкатки **L10**: README прочитан как данные и сверен, трассировка покрывает §2…§18.

## Решения, требующие внимания

1. **README перезаписывается, а не дописывается.** Тридцать три накопительных вставки заменены одним текстом;
   для версий ниже 0.1.36 цепочка вставок сохранена, поэтому прошлые выпуски воспроизводятся по-прежнему.
2. **Якорь — не метка, а ссылка, которую разрешает тест.** Требование «каждое утверждение с якорем» без
   проверки было бы декларацией; тест разбирает 84 строки с содержанием и падает на первой без якоря.
3. **§2…§18 трассируются по существу, а не по названиям.** У каждого раздела названы тема, существующие
   артефакты и существующие испытания; если испытание удалить, сборка упадёт — трассировка не станет
   списком пожеланий.
4. **«Чего нет» сверяется с отчётом сборки.** Два `not run` из `CHECKS.json` (`X14`, `T12-live`) и три
   объявленных честно (поведение моделей, ACL/NTFS, живая среда) названы в README; расхождение валит сборку.
5. **Уровни в трассировке сверяются по паспорту стенда** — по объявленным `item('L…')` в `pilot.py`,
   а не по выдуманному списку `L1…L10`.

## Приёмка: что считается провалом

Провал — если README больше 24 КБ; если утверждение без якоря; если якорь не разрешается; если §2…§18 покрыт
не полностью или ссылается на несуществующий артефакт или испытание; если README обещает больше, чем измерено;
если журнал выпусков вернулся в README.

## Чего в этой итерации нет

README не доказывает, что человек его прочитал и понял: это `not run`, и так и будет записано. Проверка
якорей — про расхождения, а не про смысл. Ответы живой модели, VS Code и ACL/NTFS остаются `not run`.
