# Политика Git для AgentContractKit: локальная копия ↔ Arena

Объект политики — AgentContractKit, не ядро ISAI. Этот документ задаёт порядок работы, а не настраивает хуки, разрешения или CI. Технический `guard` — И‑127/И‑128.

## Что синхронизируется

| Класс | Правило |
|---|---|
| L0 | Источники и манифесты — отдельно от профиля и проекта; публикация/тег — только на релизном шаге после проверок и решения владельца. Ни ZIP, ни `releases/<version>` опубликованного выпуска не заменяем под прежним номером. |
| L1 | Только согласованные переносимые правила без путей машины, секретов и проектных данных, после проверки переноса. Git хранит историю файлов, не выдаёт `revision` и не превращает конфликт в подтверждённую мутацию. |
| L2 и локальные следы | Реестр проекта, `state.json`, `checks.json`, локальные журналы/ответы/калибровка, токены, частные данные и рабочие копии не выгружаются по умолчанию. Допустимы только намеренно отобранные синтетические/обезличенные фикстуры с явным основанием. Правило «не выгружать» — не замена проверке `git diff --cached`. |
| Артефакты итерации | Коммитить код, входные спецификации, синтетические данные, машинные результаты, отчёт, HTML и маленькую требуемую печать. Крупные бинарные данные — по действующему договору хранения вне Git; в Git — ссылка, размер, SHA‑256 и способ воспроизведения. Не включать временные распаковки, кеши и исходные данные проектов. |

## Цикл работы

1. **Одна закреплённая ветка, один активный писатель.** Перед сменой среды один участник заканчивает текущую итерацию и проверяет `git status --short --branch`, `git branch --show-current` и ожидаемый HEAD. Arena не переключает, не переименовывает, не создаёт ветку в этой сессии. Нет изменений `main`, тегов или PR по умолчанию.
2. **Перед продолжением** выполнить `git fetch origin` и сравнить текущий HEAD с `origin/<ветка>`. Если локальное дерево чистое и только отстаёт, обновить его на той же ветке (`git merge --ff-only origin/<ветка>`), затем заново сверить стратегию. Если нет fast-forward, есть чужие изменения или незавершённые операции — остановиться, показать расхождение владельцу. Не использовать `--force`, rebase общей истории или глобальные настройки редактора/Git.
3. **Перед отправкой** в явный список включения попадают только оговорённые пути итерации. Проверить `git status --short`, `git diff --cached --name-status`, `git diff --cached --check` и смысл diff. Не трогать `.isai/`, старые ZIP и чужие области. Записать П9 с основанием. Коммит `И-<NNN>: <тема> — <что доказано>`; пуш только `git push origin <текущая-ветка>`. При отклонении пуша не перетирать историю; остановиться и сверить ветку. При передаче назвать ветку, SHA, результат повторного прогона и `not run`.
4. **Воспроизведение** — из чистой копии тех же входов. Историческую печать проверять по снимку соответствующего коммита (`git archive --format=zip -o <временный.zip> <commit>` и распаковка вне проекта), а не по сегодняшней стратегии. Git с CRLF может дать иные байты рабочего дерева, даже если смысл текста совпадает; `--verify-seal` сравнивает именно байты, менять глобальные настройки ради отчёта не надо.

## Если возник конфликт

- **L0:** различие при одном SemVer — нарушение целостности. Пин сверяется с утверждённым артефактом, историю и тег не перезаписывать.
- **L1:** одинаковая или большая `revision` не выбирает победителя; остановка, сравнение общего предка, digest и записей по ID, решение владельца, новый план с проверкой ожидаемого состояния. Не сливать файлы реестра или журнал как произвольный текст. Точный протокол разрешения — И‑116.
- **L2:** пользовательские решения в локальных копиях не переписываются; при необходимости переноса — рабочая копия и отдельная процедура согласованной операции (не `git pull` поверх реестра).

Результат И‑103 проверяет Git-процедуру на этой ветке и архиве снимка; Windows/VS Code и переключение между реальными агентами проверяются позже, не засчитываются здесь.
