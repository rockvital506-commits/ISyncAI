# И‑023 · Замысел до прогона: приёмка 0.1.4 на настоящих журналах

18 ноября 2026. Владелец журналов не имеет (ответ: файла нет — предложить иные пути). Поэтому предмет
итерации уточняется без изменения существа: проверяется не «журнал заказчика», а **происхождение
журнала** — текст, который произвёл настоящий инструмент, а не мы для прохождения приёмки.

## Что именно «настоящий журнал» здесь

| Свойство | Как проверяется |
|---|---|
| текст произведён инструментом, а не человеком | у журнала есть команда, код возврата, начало и конец, версии инструментов, отпечаток файла |
| текст не правился после прогона | отпечаток в `journals/provenance.json` сверяется с файлом на диске |
| факт в наблюдении существует | каждая цитата находится дословно в указанной строке журнала (независимая проверка) |
| источник нам не подконтролен по содержанию | сообщения, идентификаторы, числа и пути берутся из вывода инструмента; мы не выбираем, что в них написано |

Чего здесь получить нельзя и что остаётся `not run`: журналы с вашей машины, ваших проектов, Windows и
живых моделей. Это не заменяется и в приёмке не заявляется.

## Стенд (фиксируется до записи прогона)

Восемь журналов, все — вывод настоящих инструментов в этом окружении, Linux, Python 3.11.2, Node 22.22.3:

| id | инструмент | что делает |
|---|---|---|
| `pip-resolver` | pip 23.0.1 | разрешение несовместимых требований `flask==3.0.*` и `werkzeug<2` |
| `pip-build` | pip 23.0.1 | сборка `pycrypto==2.6.1` из исходников |
| `pytest-run1` | pytest | набор `psf/requests` v2.32.3, первый прогон |
| `pytest-run2` | pytest | тот же набор, второй прогон того же кода |
| `pytest-utils` | pytest | только `tests/test_utils.py`, отдельный прогон |
| `npm-install` | npm 10 | установка `gulp@3.9.1` (251 пакет) |
| `npm-audit` | npm 10 | `npm audit` в этом же каталоге |
| `npm-ci-nolock` | npm 10 | `npm ci` без `package-lock.json` |

Девятый журнал — `authored-control` — написан рукой как правдоподобная имитация журнала CI. Он **не
входит в приёмку** и нужен ровно для одного: показать, что критерий происхождения отличает его от
восьми остальных (у него нет команды, кода возврата, времени и отпечатка).

## Извлечение наблюдений (правила до прогона)

Наблюдение — это пара `expected`/`actual` с уликой, собранная **из одной строки** журнала по шаблону
случая. Шаблон задаёт рамку фразы, содержание берётся дословно:

| случай | строка-источник | `actual` |
|---|---|---|
| `pytest-summary` | итоговая строка pytest | `Итог прогона: <счётчики дословно>.` |
| `pytest-failed` | строка `FAILED <id>` | `Падает тест <id>.` |
| `pytest-skip` | строка из `SKIPPED [...]` | `Пропущен тест <id>.` |
| `pip-error` | строка `ERROR: ...` | `<текст строки дословно>` |
| `npm-deprecated` | строка `npm warn deprecated ...` | `<пакет>@<версия> объявлен устаревшим.` |
| `npm-error` | строка `npm error ...` | `<текст строки дословно>` |
| `build-error` | строка `файл:строка:колонка: error: ...` | `<текст ошибки компилятора дословно>` |
| `npm-vuln-total` | итог `npm audit` | `<счётчики уязвимостей дословно>` |

`evidence` = `<файл журнала>, строка <N>` где N — настоящий номер строки в файле. `level` = 3,
`environment` — из провенанса журнала (Linux, без редактора, офлайн-модель), `limits` — «Оценка по
журналу, не запуск.» для всех, `conditions` — «Читался вывод команды `<cmd>`; код возврата `<rc>`.»

Честная оговорка: стенд и правила извлечения писались после того, как вывод инструментов был впервые
получен (иначе нельзя было убедиться, что стенд вообще даёт журналы). Правила не подгонялись под
нужный ответ — они покрывают все семь типов строк, которые в этих журналах встретились, — но слепой
эта проверка не была, и это записано в отчёт.

## Пары для правила склейки (классы до прогона)

| класс | как получается | ожидание |
|---|---|---|
| `repeat-form` | одно и то же наблюдение из `pytest-run1` и `pytest-run2` (`FAILED`-строка) | склеивается |
| `repeat-volatile` | итоговые строки двух прогонов: счётчики те же, длительность разная | не склеивается — факт разный; находка, а не провал |
| `other-near` | близкие, но разные: `glob@4.5.3` и `glob@3.1.21`, два теста одного файла | не склеивается |
| `other` | разные события: конфликт зависимостей и провал сборки, падение и пропуск | не склеивается |

Пары строятся скриптом по этим правилам и **не пересматриваются** после прогона.

## Что будет означать провал

- хотя бы одна ложная склейка в классах `other*` — правило не годится для настоящих журналов;
- хоть одно наблюдение, чей факт не подтверждается указанной строкой, — извлечение негодно, приёмка не считается;
- изменение `checks.json` при склейке — нарушено «не переписывать»;
- расхождение повтора из печати с сборкой.

## Ожидания по числам (до прогона, для сверки)

- журналов в приёмке 8, «написанных рукой» — 0;
- наблюдений не меньше 40;
- ложных склеек 0;
- склеек в `repeat-form` — все;
- отказ от склейки в `repeat-volatile` — ожидаем, число фиксируется.

## Границы

Настоящие журналы здесь — наших инструментов и нашего окружения, на коде третьих лиц. Журналы
заказчика, Windows, права и живые модели остаются вне приёмки. `not run` не выдаётся за `pass`.
