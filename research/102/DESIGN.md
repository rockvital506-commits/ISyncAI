# И‑102 — замысел и сценарии испытаний (П0–П2)

**П0.** Сверено с `research/STRATEGY.md` v1.1, §2, §4 (Ф0) и §5. Предмет — один воспроизводимый прогон, не изменение Kit или работа над И‑103. `ITERATION.json` задаёт цель, гипотезу, границы, отказы, критерии и откат.

**П1.** Проверяем, что одна команда выполняет П3–П8 на неизменном 0.1.36. Харнесс должен получить те же данные, что и И‑101, не пересчитывать ожидания из результатов и не превращать пропуски в успехи. `.isai/`, архив выпуска и историческая И‑101 не меняются.

**П2.** Первые фикстуры — машинные результаты И‑101 (`research/strategy/BASELINE.json`, `research/101/CLEANROOM.json`) и ожидания шагов из `ITERATION.json`. Уточнение перед исправлением чернового прогона: два равных архива ещё не доказывают, что они собраны из итоговых файлов. Тесты ниже фиксируют это расхождение и ожидаемое поведение отказов.

| Сценарий | Критерий |
|---|---|
| Прогон с нуля и повтор | Полные JSON инвентаря и чистой копии совпадают с И‑101; два запуска из одного дерева дают те же артефакты |
| Чистый проект | `absent → install → valid → connect → create contract → create rule → list → valid`; запрос адаптера Arena возвращает `adapter_unknown` (rc 2); калибровка не вызывается |
| Выпуск 0.1.36 | Офлайн-набор `kit/tests/test_contract.py` запущен заново в отдельной распаковке; встроенные пропуски отделены от проверок харнесса |
| Дефектная спецификация | Недостаток проверок, неизвестный тип, самосравнение или циклический член печати не допускаются (`spec_invalid`, rc 2) |
| Неверное ожидание | Неверное значение даёт `fail`, итог `rejected`, код возврата 1; `not run` не считается `pass` |
| Изменение после печати | Повтор обнаруживает изменение конечного отчёта или самого ZIP и не исправляет печать молча |

Негативные сценарии выполняются в `test_harness.py` на временных файлах и подменённых результатах проб. Реальный прогон выполняется на закреплённом архиве. Внешние среды и редакторы не эмулируются.
