# И‑027 · Адаптер GitHub Copilot / VS Code: замысел до прогона

18 ноября 2026. Правило тождества не меняется. Предмет — вторая среда, и она устроена иначе, чем Kilo:
**инструкции вместо правил**, два родных файла выше нашего входа и неполное покрытие по поверхностям.

## Что известно про среду (сверено 18.11.2026)

| Свойство | Факт | Источник |
|---|---|---|
| Общий файл репозитория | `.github/copilot-instructions.md`, читается везде, где инструкции поддерживаются вообще | docs.github.com, сводка memorylake |
| Файлы по путям | `.github/instructions/**/*.instructions.md`, обязательное поле `applyTo` во front matter (glob, можно несколько через запятую), необязательное `excludeAgent` (`code-review` / `cloud-agent`) | qaskills.sh, docs |
| Инструкции агента | `AGENTS.md` в любом каталоге, ближайший выигрывает; альтернативы в корне — `CLAUDE.md`, `GEMINI.md` | github.blog changelog 28.08.2025 |
| Порядок старшинства | личные → файлы репозитория: сначала path-specific, затем общий, затем инструкции агента → организация. Все наборы передаются модели: старшинство решает конфликт, а не убирает проигравшего | docs, memorylake |
| Покрытие `AGENTS.md` | читают cloud agent, code review на GitHub.com, CLI, Chat в VS Code; **не читают** Chat на github.com и встроенные подсказки | сводка startdebugging |
| CLI | по своей документации общего порядка между файлами не определяет, а дубликаты дедуплицирует | clients.dev, docs |
| VS Code | `AGENTS.md` вне корня рабочей области по умолчанию выключен | docs |

Следствие для комплекта: у Kilo вход был третьим, но единственным файлом-входом; у Copilot он
**четвёртый в порядке и второй среди файлов репозитория**, а часть поверхностей не читает его вовсе.
Записать «то же самое» в `.github/copilot-instructions.md` значило бы завести второй вход — то есть
ровно второй реестр, от которого комплект отказывается.

## Что делает адаптер

| Делает | Не делает |
|---|---|
| карточка `adapter copilot`: вход, рекомендованный средой файл, `entry_shared: false`, старшинство 5 шагов, пробелы покрытия по поверхностям | не пишет в `.github/`, `.vscode/`, `CLAUDE.md`, `GEMINI.md` |
| видит `.github/copilot-instructions.md`, `.github/instructions`, `.github/agents`, `.github/prompts`, `.github/skills`, `.vscode/settings.json`, `CLAUDE.md`, `GEMINI.md`, `AGENT.md` | не читает их содержимое |
| требует `ack_existing` в порядке обнаружения | не переносит правила в формат инструкций |
| отказ `second_entry` на любой путь входа, кроме `AGENTS.md` | не создаёт второй указатель «на всякий случай» |

Запрет на второй реестр перестаёт быть фразой в документе: он становится **кодом отказа** `second_entry`.

## Что будет означать провал

- комплект создаёт второй вход или пишет в `.github/`/`.vscode/`/`CLAUDE.md`/`GEMINI.md`;
- карточка заявляет покрытие, которого нет (например, «Chat на github.com читает AGENTS.md»);
- правило тождества поехало;
- обнаружение выдаётся за проверку.

## Границы

Живого Copilot здесь нет: чтение инструкций в VS Code, реальное старшинство и поведение с моделью —
уровни достоверности (И‑030…И‑032) и живые модели (И‑045). Стенд синтетический, собран по документации.
Windows, права и журналы заказчика — `not run`.
