# AgentContractKit 0.1.25 — частичный сбой: половина записи, половина файла

18 ноября 2026. Итерация **И‑045**, §12.3. Линия выводится от неизменённого 0.1.0 теми же правками, что
дали 0.1.4–0.1.24.

## Что нового

- **сбой виден до восстановления**: `status` при незавершённой операции отдаёт `pending_detail` — для
  каждого файла класс `before` (старый), `after` (новый) или `foreign` (не опознан);
- **спасение названо**: для `foreign` — `salvage: {copy, intact}` с путём к копии `before` и проверкой её
  целостности; то же в заметках плана `restore`;
- **чтение остаётся чтением**: `writes: false`, проект не меняется;
- **половина записи восстанавливается**: `restore` возвращает `restored`, проект снова `valid`;
- **половина файла не перезаписывается**: `restore` возвращает `partial` с `unresolved`, а копия `before`
  цела и возвращает проект;
- **новая работа ждёт**: пока операция не завершена, любая другая отклоняется кодом `pending`.

## Чего в выпуске нет

Комплект не «дописывает» половину файла: он не знает, что хотел записать прерванный процесс. Спасение —
копия `before`, её применение остаётся решением участника. Проверки личности `actor`, живой среды (VS Code
с Kilo и Copilot), прав Windows, журналов заказчика и метрик в выпуске нет — они впереди (И‑046…И‑050).
