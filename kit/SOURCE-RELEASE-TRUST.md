# Проверка подписи исходного кандидата

`source_release_trust.py` проверяет **отдельную Ed25519-подпись точных bytes**
`kit/KIT-VERSION.json` текущего кандидата и затем сверяет его перечисленный исходный состав.
Это не установщик, не обновление, не поддержка старых версий, не подпись исторического
[стендового ZIP](base/BUNDLE-TRUST.md) и не подтверждение G1–G6. Никакой код из проверяемого
корня этот инструмент не исполняет. Требуются заранее доверенные копии самого проверяющего,
соседних `openssl_ed25519.py` и `verify_candidate.py`, Python, ОС, библиотеки OpenSSL,
исполняемого OpenSSL и **отдельно удостоверенный** отпечаток открытого ключа владельца.
Нельзя брать ключ, его доверенный отпечаток и отпечаток проверяющей программы только из
проверяемой поставки. Пока защищённый канал ключа и выпуск подписанного продукта не
организованы, использовать только синтетические испытания.

Подпись — ровно 64 bytes Ed25519, открытый ключ — ровно 32 bytes; идентификатор ключа —
нижний регистр SHA-256 этих 32 bytes. Подписывается не текст JSON и не ZIP напрямую, а ровно:

```text
ASCII "DomainAgentKit:source-manifest-signature:v1", один нулевой байт,
32 bytes SHA-256 открытого ключа, 32 bytes SHA-256 точного файла манифеста.
```

Это обычный Ed25519, не Ed25519ph. Разделение доменов не совместимо с подписью стендового
архива. Подпись и ключ передаются отдельно и не становятся членами манифеста. Ключ, доверенный
key id, подпись, абсолютный путь заранее доверенного OpenSSL и отдельно доверенный SHA-256 его
исполняемого файла передаются явно; никакой ключ, исключение или fallback не выбирается из
кандидата. Значения `--public-key-hex`, `--signature-hex`, `--trusted-key-id`, `--openssl-pin`
должны быть нижнерегистровым hex точной длины. Это **не секретный ключ**; подпись вне этой
программы выполняется владельцем с соблюдением собственной политики ключей.

```text
python3 -I -S -B /trusted/DomainAgentKit/kit/source_release_trust.py --candidate-root /snapshot/DomainAgentKit --public-key-hex <32-byte-key-hex> --trusted-key-id <trusted-sha256-key> --signature-hex <64-byte-signature-hex> --openssl /absolute/trusted/openssl --openssl-pin <trusted-sha256-executable>
```

Проверяется отпечаток внешнего ключа, ограниченное чтение манифеста через nofollow dir-fd,
подпись OpenSSL с фиксированными параметрами без shell, затем существующий
`verify_candidate` с выведенным подписанным pin и повторное чтение манифеста. Проверяющий
принимает только собственную версию кандидата; безопасная смена доверенного проверяющего и
ключей не реализована. Он проверяет перечисленный состав, но не строгую чистоту всего дерева.
Выход `signature_and_candidate_verified` содержит `manifest_sha256`, который можно отдельно
передать в [snapshot-сессию](SNAPSHOT-SESSION.md) или
[snapshot-move-сессию](SNAPSHOT-MOVE-SESSION.md), где состав и bytes проверятся ещё раз;
системный L0 рабочего workspace требует отдельного доверенного pin. Вывод не устанавливает
подлинность владельца ключа, безопасное хранение ключа, безопасность кода или права на запись.

OpenSSL и Python — внешние доверенные зависимости. Хеш проверяемого исполняемого файла не
защищает его библиотеки, конфигурацию ОС или замену пути между проверкой и запуском;
родительские симлинки/mount-алиасы и соперничающий процесс не исключены. Провайдер вызывается
без shell, с ограниченным временем, в новом временном каталоге, без наследования конфигурации
OpenSSL. Любой ненулевой код означает `signature_not_verified` и не различает неверную подпись
и отказ проверки. Переход на неподписанный вариант не выполняется. Допустимость ключа,
ротация, отзыв, защита доверенных pin, атомарная установка и откат остаются вне механизма.
