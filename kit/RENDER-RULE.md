# Производный материал из записи Kit

`render_rule.render(catalog, area=..., entry_id=...)` возвращает UTF-8 Markdown в памяти.
Каталог — три явных реестра v2 L0/L1/L2 без контейнеров истории, в доверенном контексте
вызывающей стороны. Функция проверяет схему, раздельность объявленных корней и обнаруживаемые
структурные конфликты `key/value`; не разрешает их. На выходе служебный комментарий с областью,
ID, ревизией и SHA-256 канонической записи, затем заголовок и точный текст. Результат
детерминирован. Никакой реестр или файл среды не записывается.

Требуется действующая дочерняя запись L1 или L2 с действующим родительским контрактом;
черновики, отменённое, L0 и отсутствующие записи отвергаются. Для первой версии поддерживается
**только scope `.`**. Более узкие области отказываются: нельзя доставить узкое правило как
глобальное, пока способ ограничения в среде не доказан. Формат не доказывает, что Kilo или
Arena прочитали или выполняют текст, а выявление конфликтов без `key/value` не гарантировано.
Путь проекта и полномочия передаются вызывающей стороной, значения в реестре не выдают прав.

Можно передать один JSON в стандартный ввод:

```text
python3 -B kit/render_rule.py < запрос.json
```

Форма запроса: `{"catalog":{"L0":...,"L1":...,"L2":...},"area":"L1","entry_id":"R-1"}`.
Вывод попадает только в stdout; ошибка — stderr и ненулевой код. Перенаправление вывода в файл,
установка в проект и раскрытие содержимого — отдельные действия владельца по выбранному плану.
Не передавайте этому интерфейсу секреты и реальные данные без необходимых разрешений.
