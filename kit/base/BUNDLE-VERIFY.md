# И‑118 · Проверка целостности полученного пакета

[`bundle_verify`](bundle_verify.py) — внутренний стендовый читатель [формата И‑117](BUNDLE.md), а не рабочая команда или установщик. Вход — обычные непустые `bytes` с ZIP, не путь, каталог, произвольный манифест или реестр. Цель только `stand`. Чтение в памяти: нет извлечения, записи, сети, исполнения содержимого или вызова сборщика.

```text
bundle_verify(archive, *, target='stand')
    → {bundle_format: 1, outcome: 'verified', revision, manifest_digest, archive_sha256}
```

`verified` означает только совпавшие форму и внутренние связи. Возвращаются наблюдаемая ревизия L1 и два отдельно вычисленных отпечатка; полезные байты и манифест не выдаются. Ревизия L1 не SemVer L0, digest манифеста не SHA‑256 ZIP, ни один не pin и не подпись.

## Порядок и границы

1. Принять только диалект И‑117: ровно 16 фиксированных полезных имён и `manifest.json`. Оба набора сравниваются с контрактом и друг с другом, а не только с утверждением отправителя. Лишнее, пропущенное и повторённое имя — отказ, даже если обе стороны согласились о неполном наборе. Имена не нормализуются и не превращаются в пути ОС.
2. До чтения членов сверить границы, порядок, флаги и фиксированные метаданные, совпадение локальных заголовков с центральным каталогом. Только ZIP_STORED, один диск, без комментариев, разрывов, ZIP64, ссылок или шифрования. Размер ZIP не выше 5 МиБ + 64 КиБ, предварительный каталог не больше 8 КиБ и 32 записей. Манифест ограничен 1 МиБ + 8 КиБ; полезный член непустой и не больше 1 МиБ, сумма полезных — до 4 МиБ. Поддерживается конкретный формат, не произвольный ZIP.
3. Прочитать строгий канонический ASCII JSON манифеста с LF: ровно `revision`, `roots`, `files`, `digest`. Корни — `["kit", "profiles/staged"]`, ревизия — целое ≥0, 16 строк `{path,size,sha256}` отсортированы. Манифест себя не перечисляет. `digest` — SHA‑256 компактного ASCII JSON трёх остальных полей, с отсортированными ключами и без LF. После проверки digest сверить размер и SHA‑256 **сырого** содержимого каждого указанного члена. CRC проверяет ZIP-читатель; он не заменяет SHA‑256.
4. Проверить голые L0/L1 по v2 и A4, связать их корни и `revision` L1 с манифестом. Валидный пустой L1 допустим. Локальная история L1 не извлекается и не удаляется автоматически: целый контейнер вне формата. Остальной текст не интерпретируется.

| Код | `where` / `details.reason` |
|---|---|
| `bundle_incomplete` | `target / stand_only`; `archive / bytes, limit, zip, layout, members, duplicate_member, format, read`; `manifest / json, shape, roots, members, duplicate_member, limit, encoding`; `system / registry, roots`; `profile / registry, roots, local_history, revision` |
| `digest_mismatch` | `manifest / digest`; `files / size, sha256` при допустимой структуре |

Первый достигнутый отказ по этому порядку завершает вызов. Не возвращается частичный результат, произвольное имя, тело записи или текст исключения парсера. Пакет с изменённым файлом и пересчитанным манифестом может быть внутренне согласован; это не свидетельство подлинности, отсутствия секретов, пригодности к установке или переносимости. Подпись, доверие и исключения — И‑119, откат — И‑120. [Доказательства и ограничения И‑118](../../research/118/REPORT.md).
