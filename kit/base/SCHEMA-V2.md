# Контракт данных AgentContractKit v2

Здесь `2` — **версия формата**, не версия поставки. Исполнимая схема — [`schema_v2.py`](schema_v2.py), Python 3.10+ со стандартной библиотекой. Не требует ISAI, старого Kit, Git или установленных реестров. Примеры ниже и испытания И‑104 не являются поставкой или регистрацией.

## Документ одной области

| Поле | Допустимо |
|---|---|
| `schema_version` | Целое число строго `2`. `2.0`, `true` и `"2"` — не целые теги формата. |
| `area` | `L0`, `L1` или `L2`. Внешний доверенный контекст может указать ожидаемую область; значение в документе не меняет её. |
| `roots` | Непустой список относительных путей хранения. Запрещены повторные и вложенные декларации. |
| `entries` | Список записей. `[]` — допустимый старт, `null` и потерянное поле — нет. |
| `release_version` | Только у L0: SemVer, например `0.2.0` или `0.2.0-rc.1+test`. Не доказывает публикацию и не проверяет pin. |
| `revision` | Только у L1 и L2: своё целое число ≥ 0. Не общее между слоями и не SemVer. Версия конкретной записи и формат журнала этой схемой не задаются. |

Объекты закрытые: неожиданные поля не игнорируются. Например, пустой документ проекта:

```json
{"schema_version": 2, "area": "L2", "roots": [".agent-contract"], "revision": 0, "entries": []}
```

## Запись

- `id` — непрозрачный идентификатор: 1–64 ASCII-символа, первый — латинская буква или цифра, остальные также могут быть `.`, `_`, `-`. Уникален **в документе**; не выдаёт полномочий и не кодирует область. Поиск между документами по одному `id` не определён.
- `kind`: `contract`, `rule`, `constraint`, `protocol`, `preference`. `state`: `draft`, `active`, `suspended`, `revoked`. Схема не вычисляет действующий набор и не разрешает переходы между состояниями.
- `authority`: для L0 — `system_release`, L1 — `profile_owner`, L2 — `project_owner`. Это допустимое **заявление о классе полномочия**, не проверка владельца, разрешений или подлинности.
- `parent` обязателен: `null` только у `contract`, у остальных — ID существующего `contract` в том же документе. `scope` записи равен или вложен по компонентам в `scope` родителя. Например, `docs/guide` входит в `docs`, `docs2/guide` — нет. Внешние поиски, разрешение конфликтов и перепривязка ссылок при миграции не делаются.
- `title`, `text`, `basis`, `criterion` — непустые Unicode-строки, представимые в UTF-8. `text` хранит тело, а не путь к нему. `key` и `value` необязательны, но только вместе: `key` — токен до 64 символов из того же алфавита, начинается с латинской буквы, `value` — непустая строка. Противоречия между значениями проверяются позднее, не этой схемой.

`roots` ограничивает **хранение**, `scope` описывает **применимость**. Пути используют `/`, без абсолютных или дисковых префиксов, `.`/`..` внутри пути, пустых компонентов, обратных косых черт, управляющих и зарезервированных Win32-символов, имён устройств и неоднозначных пробелов/точек на границах компонентов. Только `scope` может быть ровно `.` (весь проект). Для `scope` сравнение точное, с учётом регистра; для деклараций `roots` совпадение или вложенность проверяются консервативно с `casefold`. Валидатор **не открывает путь**: физические корни, ссылки, junction, ACL и политика среды проверяются отдельно.

## Интерфейс для следующих итераций

- `validate_json(data, expected_area=...)`: прочитать UTF-8 JSON (строка или байты), отказать при синтаксической ошибке, повторе поля или литерале `NaN`/`Infinity`; вернуть проверенный объект без нормализации.
- `validate_registry(document, expected_area=...)`: форма и связи одного разобранного документа. На успехе возвращает `None` и не меняет переданный объект; читателю, знающему область, следует передать её внешним аргументом.
- `validate_catalog(documents)`: проверки для явно переданного непустого отображения `{area: document}`, дополнительно — общая непересекаемость **объявленных** корней. Не обнаруживает и не объединяет реестры на диске.

При нарушении возникает `SchemaError(stage, code, path)`: `parse` — чтение, `shape` — поля/значения, `links` — ссылки/уникальность/декларации корней. `path` — JSON Pointer, `""` обозначает весь вход. Возвращается первая диагностика; связи не проверяются при ошибке формы. Примеры: `shape:authority_area` на `/entries/1/authority`, `links:parent_missing` на `/entries/1/parent`. Это **не** коды операций `apply`, `parent`, `profile_root_conflict` или `system_immutable`. Установка, отображение путей на ФС, запись и журнал, применение правил и перенос R-2 остаются за следующими итерациями.
