# Операции и области: внутренний порт v2

[`registry_policy.py`](registry_policy.py) — исполняемая таблица; [`registry_store.py`](registry_store.py) экспортирует `operation_matrix()` и `check_operation(operation, target=...)`. Первое возвращает свежий снимок `операция → область → {state, code}`, второе возвращает доступную ячейку либо `StoreError` с тем же кодом. Это **допуск пары**, не обещание, что содержимое, билет, корни или права позволят выполнить действие. Порт не выдаёт полномочий и не ограничивает другие процессы.

| Операция | L0 | L1 | L2 |
|---|---|---|---|
| `read` · диагностическое чтение | `available` | `available` | `available` |
| `create` · регистрация | `forbidden` | `available`: `rule` / `draft` | `planned` |
| `list` · пользовательский просмотр | `planned` | `planned` | `planned` |
| `edit`, `suspend`, `resume`, `revoke`, `delete` | `forbidden` | `planned` | `planned` |

- `read_registry(layout, target=...)`, `plan_create` и `apply_create` проверяют допуск до загрузки файлов. У `read_registry` результат — **реестр выбранной области**, а не слитый или действующий набор правил. Повреждённая привязка или данные любой области по-прежнему блокируют загрузку. `status`, `profile_history` и `report_conflicts` — чтение представлений, не операции с целью записи.
- `available` — есть путь во внутреннем порте (`code: null`); `planned` — данный путь сейчас отсутствует (`operation_unavailable`), не запрет на L2 в модели. `forbidden` — нормативный запрет (`system_immutable` у любой эксплутационной мутации L0). Тег `authority` или билет его не снимают. Имена вне реестра — `unknown_operation`; неизвестный адрес области — `unknown_area`. Новые имена и ячейки не появляются от одного совпадения токенов в исходниках.
- В матрице ровно однообластные действия манипуляции записями Ф2 и внутреннее `read`. Установщик, bootstrap, промоушен, перенос, выдача прав и команды донора сюда не включены. `list` не реализован чтением сырого реестра. Машинный [снимок И‑107](../../research/107/MATRIX.json) получен двумя проверочными процессами.

## Причины A1–A4

| Инвариант | Код операции | Где и что смотреть |
|---|---|---|
| A1 | `profile_root_conflict` | Совпадение/вложенность корней или совпавшая идентичность выбранных каталогов; `where` — привязка L1. Ссылки, отсутствующий путь, несовпадение заявленного корня сохраняют отдельные коды хранилища. |
| A2 | `system_immutable` | Цель `L0`, обнаруженная **до** трактовки данных или билета. Чужое объявление `authority` при цели L1 — `invalid_entry` / `authority_area`, не смена цели. |
| A3 | `rule_conflict` | `where: entries`, `details.conflicts` — обе записи в каждой паре; нет победителя, записи или «исправления». |
| A4 | `parent` | Файл цели и `schema.stage/code/path`: например `shape:missing_field` для отсутствующего `parent`, `links:parent_missing` для отсутствующего/внешнего ID, `links:parent_kind` для записи другого вида, `links:scope_outside` для выхода из области контракта. Нарушение уже сохранённого реестра — `invalid_registry`, не диагноз предлагаемого диффа. |

### Структурный отчёт A3

`report_conflicts(layout)` читает реестры и возвращает список пар `{key, scope, entries: [{area, id, scope, value, text}, …]}`. Сравниваются активные неконтрактные записи **под активным локальным контрактом**, у которых есть явная пара `key/value`. Совпавший ключ, разные значения и пересечение `scope` по компонентам дают пару, даже внутри одной области. В `scope` пары — более узкая общая область. Сортировка ключа, области и ID нужна для воспроизводимости, а не для старшинства. Свободный текст не интерпретируется; отсутствие пар не доказывает отсутствие смысловых противоречий.

Свежая регистрация черновика не разрешена, пока в загруженных данных есть такое противоречие. `apply_create` после проверки цели, подтверждения и ревизии повторяет проверку на перечитанных данных. Новая запись `draft` сама не образует действующий конфликт; точный повтор без новой записи остаётся `no_change`. `report_conflicts` не блокирует обычное чтение и не является операцией `promote`. Полный разбор ограничений, приоритетов и решения владельца — И‑116; здесь ни одна запись не становится действующей.
