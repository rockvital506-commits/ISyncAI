# Карточка операции · формат 1

[`compile_prompt(request)`](operation_card.py) принимает строку UTF‑8 и возвращает обычный JSON-совместимый словарь. Это **внутренняя граница между фразой и будущим планом**, не CLI и не исполнитель. Python ≥ 3.10 и стандартная библиотека; [матрица допуска](OPERATION-MATRIX.md) используется как политика, но хранилище не открывается. `card_format` — тег формы карточки, не версия Kit или ревизия реестра.

| Поле | Что означает |
|---|---|
| `request` | Исходная строка целиком, без исправления формулировки. |
| `operation` | `create`, `list`, `edit`, `suspend`, `resume`, `revoke`, `delete` либо `null`, если нет однозначного действия либо режим вне реестра. Это намерение, не обещание обработчика. |
| `params` | Только явные реквизиты, словарь без `null`-заполнителей. `target` L0/L1/L2 — область; `profile` — символический ID выбранного профиля L1, не путь. `kind` — вид v2; `entry_id` — явный ID. `scope` — область применимости, не корень. `text` — формулировка, не команда. `persistence` — явно указанный режим фразы, не `state`. |
| `missing` | Полный упорядоченный список `{field, reason}` для отсутствующих (`absent`), конкурирующих (`ambiguous`), неверно заданных (`invalid`) или нераспознанных (`unrecognized`) параметров. Два варианта не заменяются первым из них. |
| `questions` | Первые не более трёх уточнений `{field, text}` в порядке `missing`. Нет памяти предыдущих ответов или запуска диалога. |
| `outcome`, `code` | `complete` / `null` — хватает реквизитов этой карточки, **не** готовность записи. `missing_params` / `missing_params` — требуется уточнение. `non_registry` / `null` — классифицировано вне реестра. `rejected` / `system_immutable` либо `parent` — известный запрет без лишних вопросов. |

## Реквизиты и запреты

- В `create` явно нужны цель, профиль при L1, вид, область действия, ID, состояние, название, формулировка, основание и критерий. Для `rule`, `constraint`, `protocol`, `preference` нужен `contract` — ID выбранного родителя. У создаваемого `contract` родителя нет; если фраза явно задаёт родительскую связь (включая варианты), причина отказа `parent`. Непредъявленный родитель дочернего вида — **уточнение**, не попытка построить неполный объект v2. Существование родителя в том же реестре, его вид и вложенность проверяются позже по [схеме v2](SCHEMA-V2.md) и порту, а не считаются доказанными по строке.
- При запросе существующей записи указанная цель и ID нужны для `edit`, `suspend`, `resume`, `revoke`, `delete` и `list` с `view: "text"`. `edit` пока обозначает замену текста; родитель сохранённой записи не выбирается или меняется карточкой. При обычном `list` возможен фильтр по явно названному виду или состоянию. `действующие` в запросе просмотра даёт фильтр `state: "active"`, не активацию.
- Допуск явно распознанной пары проверяется через `operation_matrix()`. У мутации L0 `system_immutable` даже при неполных реквизитах. `planned` — не запрет модели, карточка может быть `complete` без реализованного пути. Ни действующий профиль, ни ближайший контракт, ни `.` или `draft` не выбираются по умолчанию.

## Режим фразы (И‑111)

| Явная метка в управляющей части | `params.persistence` | Что происходит дальше |
|---|---|---|
| «постоянное», «на постоянной основе» | `permanent` | Обычная проверка реквизитов, затем возможен дифф. Не выводит ни `draft`, ни `active`, ни согласие. |
| «временно», «только на эту задачу», «Временное указание: …» | `temporary` | `non_registry`, без изменения реестра. Kit не исполняет это указание и не задаёт таймер. |
| «как предложение», «Предложение: …» | `proposal` | `non_registry`, не утверждённое действие или доказательство авторства. |
| «как гипотезу», «Гипотеза: …» | `hypothesis` | `non_registry`, не установленный факт. |

- Метки принимаются в узкой грамматике `create`/`edit` или как отдельный заголовок текста. Слова в кавычках и после двоеточия не меняют режим. Например, в «Предложение: Зарегистрируй …» команда является текстом предложения. Для незаписываемой фразы без содержимого уточняется `text`, не профиль или контракт.
- При конкурирующих метках в `missing[]` будет `persistence: ambiguous`, в том числе в обратном порядке и для «зарегистрируй … временно». Для «сделай/оформи черновик …» без режима и для общего `create` без метки, явной регистрации или черновика — `persistence: absent`. Указание «зарегистрируй»/«запиши» либо явное «создай/добавь черновик» не подставляет `permanent`: это однозначные запросы на подготовку диффа к реестру в данной грамматике. Адресные `edit`, состояния и `list` не получают выдуманный режим.
- Выбор уточняется новой полной фразой, без заполнения по истории. Одно «Постоянное.» не даёт операции. Явно распознанные запреты L0 и родителя контракта выше уточнения. См. [20 фраз и результаты](../../research/111/INTENTS.json).

## Узкий русский вход

У операции — один распознанный глагол (допускается «Пожалуйста,» и явная метка режима). Затем — названный вид и, при наличии, следующий ID. «В профиле Pilot» явно означает L1 и ID `Pilot`; «в проекте» — L2. «По контракту C-1», «под контрактом C-1» и «для контракта C-1» называют ссылку, не ищут запись. Для `scope`, названия, основания и критерия используются явно подписанные фрагменты в `«…»` или `"…"`. Двоеточие **вне** кавычек отделяет текст для `create`, `edit` и отдельной фразы с меткой режима. Внешние пробелы свободного тела снимаются; внутри одной пары кавычек всё сохраняется. Глаголы и ссылки в теле не разбираются как операции.

Примеры:

- «Зарегистрируй протокол в L1: Перед выводом сверяй свидетельства.» → `create`, `kind: protocol`, `target: L1`, явный текст; первые три вопроса — профиль, контракт, область действия, остальные пробелы остаются в `missing`.
- «Покажи только текст протокола T-7 в профиле Pilot.» → `list` с `view: text`, без требования создать родителя или запись.
- «Создай правило или покажи протокол в профиле Pilot.» → уточнение `operation`, ни одна альтернатива не принята.

Это консервативный словарь и небольшой набор конструкций, **не все русские фразы**. Необработанный управляющий фрагмент, цитата целиком, отрицание или две операции не интерпретируются как команда. Уточнение не снимает запрет L0. [Корпус И‑108](../../research/108/CASES.json) исторический; И‑111 уточняет «оформи» и «сделай» там, где не назван режим. [Сессия](OPERATION-PLAN.md) отдельно исполняет просмотр или готовит дифф; фраза «удали» не содержит согласия `allow_delete`. Карточка не включает `authority`, `parent`, пути записи, дифф, билет, смену состояния или обращение к среде. Свободный диалог с памятью и bootstrap не входят в этот интерфейс.
