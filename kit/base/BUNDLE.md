# И‑117 · Полный синтетический срез: сборка, не проверка доверия

[`bundle`](bundle.py) собирает переносимый стартовый **срез** L0 и одного синтетического L1. Это внутренний сборщик, не рабочая команда, не дистрибутив релиза и не установщик. Он не выбирает файлы из проекта, не обращается к путям, не меняет источники, не запускает содержимое и не пишет архив на диск.

```text
bundle(files, *, target='stand') → {bundle_format:1, outcome:'bundled', manifest, archive:bytes}
```

## Закрытый вход

| Логические имена | Назначение |
|---|---|
| `kit/base/{entry.txt,START.md}` | Точка входа и сопровождающий документ |
| `kit/base/{SCHEMA-V2.md,STORAGE-V2.md,OPERATION-CARD.md,OPERATION-PLAN.md}` | Четыре документа, на которые ссылается START; остальные ссылки не проверяются |
| `kit/base/{bootstrap.py,operation_card.py,operation_plan.py,profile_journal.py,registry_journal.py,registry_policy.py,registry_store.py,schema_v2.py}` | Исходники стартовой базы, только как байты |
| `kit/base/registry.json` | Синтетический реестр L0 v2, корень `kit`; SemVer остаётся внутри реестра |
| `profiles/staged/registry.json` | Предъявленный голый синтетический L1 v2, корень `profiles/staged`; его собственная `revision` сохраняется |

`files` — обычный словарь: ровно эти 16 строковых ключей, непустые `bytes`, до 1 МиБ на имя и 4 МиБ суммарно. Имена сравниваются точно, не нормализуются, не разрешаются как пути и не наследуются из произвольного манифеста. Пропуск любого члена даёт отказ, но полный набор с валидным `entries: []` допустим. Проверяются строгий JSON, форма и связи v2 двух реестров; другие стартовые материалы не интерпретируются. Ни L2, ни `.isai/`, ни дополнительные файлы/настройки не допускаются. Обёртки `profile_format`/`registry_format` и вложенный локальный `journal` L1 отвергаются целиком: здесь нет автоматического отбора или извлечения профиля из рабочей копии. `*_journal.py` — код, не сохранённая история.

Проверка формы и фиксированных имён не подтверждает происхождение, отсутствие секретов/PII, отсутствие смысловых конфликтов или переносимость произвольного содержимого. Вызывающий отвечает за предварительный отбор уже согласованных безопасных данных; текущая проба использует только синтетику для реестров. P01 И‑114–И‑116 и рабочие данные не использованы.

## Манифест и архив

- Поля манифеста **ровно** `revision`, `roots`, `files`, `digest`. Ревизия — из предъявленного L1 без прибавления; `roots` — `["kit", "profiles/staged"]`, а не области действия записей. `files` — отсортированные по полному имени `{path, size, sha256}`: точный размер в байтах и нижнерегистровый SHA‑256 каждого полезного члена.
- `digest` — SHA‑256 компактного ASCII JSON объекта `revision/roots/files`, без поля `digest`, с ключами по порядку (`ensure_ascii=True, sort_keys=True, separators=(',', ':')`), **без** LF. Манифест с `digest` сохраняется как `manifest.json` в том же формате, с одним LF в конце. Он не перечисляет себя.
- ZIP содержит ровно 17 отсортированных обычных членов, включая манифест. ZIP_STORED, время `1980-01-01T00:00:00`, метаданные `create_system=3`, mode `0100644`, без полей времени хоста. Все полезные байты сохранены. Одинаковый отобранный вход даёт те же байты, независимо от порядка ключей; отличие сырых байтов, в том числе JSON-пробелов, меняет файл и digest. `digest` манифеста и SHA‑256 контейнера — разные величины; ни одна не подпись и не pin установленного релиза.

`bundle_incomplete` — отказ без частичного манифеста или ZIP: `where=target/files/system/profile/archive`, с фиксированным `details.reason`. Проверки входа завершаются до открытия буфера. Поздняя ошибка упаковки не выдаёт буфер. Каталоги и доступ ОС здесь вообще не исследуются.
