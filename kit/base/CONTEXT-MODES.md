# Опытный выбор контекста по двум режимам

**Только проектная проверка, не готовая граница безопасности и не D10/G4/G6.** `context_modes.prepare`
принимает `layout`, `mode: "project" | "kit"`, один явно выбранный логический `scope` и
`choices: {include: [{area,id}, ...], exclude: [{area,id}, ...]}`. Это не естественный язык,
не определение цели или необходимых сущностей и не отправка контекста агенту. Нужны доверенные
код, среда и право читать все три области; локальный hash их не удостоверяет.

Сначала вызывающий с правами изучает ограниченный отчёт [applicable](APPLICABILITY.md).
Затем он явно классифицирует **каждую** активную применимую запись L1/L2, включая контракты.
ID из разных областей различаются. Пропуск, лишний, повторный или неприменимый ID приводит к
отказу. Включённому ребёнку нужен включённый локальный контракт. Сущности вида `constraint`
или `protocol` отказывать во включении нельзя: этот консервативный выбор не доказывает, что
прочие виды не содержат ограничений безопасности, и может включить лишний проектный контекст.
При известном структурном конфликте контекст не выдаётся; обе стороны можно отдельно изучить
через `applicable` (snapshot может раньше отказать через свой общий preflight).

L0 должен побайтно совпадать с версионированным локальным кандидатом, встроенный SHA — это
сверка совместимости кода и данных, **не** независимая проверка авторства. Для `project`
исключается `SYS-KIT-MODE`, для `kit` — `SYS-PROJECT-MODE`; все другие активные системные
записи включаются консервативно. Это явная авторская гипотеза, не окончательное распределение
или доказательство минимальности. Другой L0 отказывает `context_system_unbound`. Список
пользовательских исключений и классификацию нужно заново проверить при каждом изменении данных.

Возвращается `review_required`, полные выбранные записи с локальным происхождением, входные
хеши и количество исключённых записей; текст исключённых записей не выдаётся. **Не передавайте
этот ответ агенту автоматически:** правило безопасности может быть сформулировано как `rule`
или иначе и оказаться исключённым, задача может затрагивать другой путь; алгоритм не понимает
смысл, границу необходимого, права или задачу. Он не доказывает полноту безопасности, отсутствие
смысловых конфликтов, минимальность, фактическое согласие, доставку или следование. Человек
должен самостоятельно оценить эти вопросы, а практический механизм ещё не готов.

CLI/snapshot принимают `{"type":"context","mode":"project","scope":"docs/file",
"choices":{"include":[],"exclude":[]}}` — это пример формы, применимый лишь если нет активных
L1/L2 записей; иначе нужна полная явная классификация. Запрос отзывает ожидающий план и не
пишет. Snapshot запускает preflight и закреплённый модуль; он не авторизует вызов и не
устраняет TOCTOU. Вывод может содержать конфиденциальные данные включённых записей. Нет проверки
живого агента и метрик контекстного окна; D10, оба конечных режима и G1–G6 не закрыты.
