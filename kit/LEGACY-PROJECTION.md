# Предварительная проекция 0.1.36 в L2 v2

**Это экспериментальная подготовка, не миграция и не инструкция к установке.** Результат не
записывается в проект, не подтверждён владельцем и не пригоден для применения как есть.
Читаются только явно переданные байты контейнера из `LEGACY-CAPSULE.md`; внешний pin обязателен.

## Python API

```python
from kit.legacy_projection import analyze, project

summary = analyze(archive_bytes, pin=trusted_pin, roots=['.agent-contract'])
summary, proposed_registry_bytes = project(archive_bytes, pin=trusted_pin,
                                           roots=['.agent-contract'])
```

`roots` задаёт вызывающий; это **логические** корни хранения, не создаваемые пути. `analyze`
возвращает сводку без текстов; только явный `project` возвращает байты предложения. Если
`outcome: blocked`, предложения нет (`None`). При ошибке формы входа возникает `ProjectionError`
с диагностическим кодом. Сводка сама может содержать чувствительные ID, пути и хеши.

Предложение повторяет P-ID, вид, заголовок, состояние, scope, текст, основание, критерий,
родителя P→P, пару key/value и числовую ревизию. В `authority` проставляется техническое
значение `project_owner`, необходимое схеме L2; оно **не** удостоверяет владельца или права.
Проверяются схема v2 и сравнение выбранных полей из `compare_old`; сравнение сохранённых байтов
производится с тем же переданным контейнером — это не проверка независимой резервной копии.

Старые метаданные записи и проекта, decisions, tombstones, checks и системная база **не входят**
в предложенный реестр: их исходные байты остаются только в отдельно сохранённом контейнере.
Число ревизии не делает старый журнал журналом v2. Контейнер содержит лишь три документа и не
является полным резервным снимком. Вызывающий отвечает за сохранение контейнера и pin отдельно.

Ссылки на B-контракт, retired-проект, tombstones, несовместимые со схемой v2 пути и связи
блокируют предложение, а не меняются догадкой. Неподдерживаемые версии, повреждённый контейнер,
невалидная минимальная форма старой истории или неверный pin дают ошибку. Это не полная проверка
старой установки, подлинности, конфликтов, pending, совместимости поведения scope, истории или
checks в новом runtime; `migration_ready` всегда `false`. Стабильность pin должна быть обеспечена
независимо: pin, вычисленный из подменённых данных, не обнаружит подмену.

## CLI

`python3 -I -S -B kit/legacy_projection.py` принимает один JSON через stdin:

```json
{"format":1,"action":"analyze","archive_base64":"<base64>","pin":"<sha256>","roots":[".agent-contract"]}
```

`action: "project"` дополнительно возвращает `registry_base64` (или `null`, если блокировано).
Base64 не шифрует данные. Не передавайте запросы, содержимое, хеши или отчёты в чат или внешней
модели; права на потоки, логи и сохранённые файлы контролируются вызывающей стороной. Код 0
означает, что анализ выполнен, а не что миграция возможна: проверяйте `report.outcome`. Код 1 —
ошибка без содержимого входа. Полноценные снимок, разрешение на применение, переход и проверка
восстановления на копии всё ещё нужны для И-131/132 и G5.
