# Сессионный интерфейс операций Kit

Интерфейс связывает уже существующую раскладку v2 и `PlanSession` в одном процессе. Он не
устанавливает Kit, не создаёт отсутствующие реестры и не выдаёт прав. Требуется Python 3.10+.
Для ограниченной сессии из закреплённых исходных байтов предусмотрен отдельный опытный
[`snapshot_session.py`](SNAPSHOT-SESSION.md); прямой вызов ниже такой проверки не выполняет.

```text
python3 -B kit/session_cli.py --workspace /absolute/workspace --profile-root profiles/pilot --profile-id Pilot
```

На стандартный ввод по одной строке UTF-8 JSON (не интерактивный естественный диалог):

```json
{"type":"plan","request":"Покажи правила в профиле Pilot."}
```

Для опытного явного выбора `project`/`kit` предусмотрен запрос `context`; все решения
и ограничения описаны в [CONTEXT-MODES.md](base/CONTEXT-MODES.md). Результат требует
смыслового ревью и не доставляется агенту автоматически. Запрос отзывает ожидающий план.

Для структурного отчёта по одному явно указанному пути можно отправить
`{"type":"applicable","scope":"docs/readme.md"}`; он отзывает ожидающий план и не пишет.
Подробные границы фильтра, конфликты и ограничения — [APPLICABILITY.md](base/APPLICABILITY.md).
Отчёт не определяет контекст задачи или смысл и не гарантирует следования агентом.

Каждый ответ — одна JSON-строка на stdout. Для мутации `plan` возвращает `plan_format: 4`,
`outcome: planned`, точный байтовый дифф, `input_mode_bits`, предупреждение `replacement_notice`
и билет. На POSIX показываются исходные биты mode трёх файлов реестров; их изменение к моменту
повторной проверки даёт `stale_metadata`. На других ОС указано `not_checked`. На POSIX mode/UID/GID цели и открытого temp при применении также сравниваются до записи и после flush; несовпадение блокирует замену. UID/GID плана, ACL и защита от гонок не проверяются; `0640` обычно вызывает отказ. Предупреждение прямо сообщает о возможной потере подтверждённых решений при конкурирующей записи даже при двух ответах `applied`: не применяйте без исключения других писателей и подмены файлов/каталогов; программа не проверяет это условие.
Вызывающий код **показывает владельцу полный план, включая предупреждение и биты mode, и
получает его отдельное подтверждение**. Затем в том же процессе передаёт полный неизменённый
объект плана и подтверждённый билет:

```json
{"type":"apply","plan":{"...":"полный объект ответа plan"},"confirmed_ticket":"билет, подтверждённый владельцем"}
```

Пример выше показывает форму, не готовый применимый план. Для `delete` нужен также явно
`"allow_delete": true`. Команда `{"type":"cancel"}` отзывает ожидающий план. Новый план,
некорректный запрос и завершение процесса также снимают ожидание. Билет одноразовый;
после дрейфа или отказа нужен новый план. В `.29` при занятой записью другого вызова того же экземпляра модуля возвращается `write_busy`, подтверждённый билет израсходован; новый план обязателен. Разные процессы CLI не разделяют этот mutex. С `.32` они дополнительно координируются через advisory-блокировку каталога workspace на поддерживаемом POSIX. При недоступности блокировки запись откажет `write_lock_unavailable`; Windows пока не поддержан. При `write_lock_release_failed` запись могла произойти — сначала выясните фактическое состояние, не повторяйте вслепую. Сторонний писатель и подмена каталога не блокируются. С `.30` пересекающиеся методы одного объекта `PlanSession` возвращают `session_busy` до проверки аргументов и сами не меняют билет; это не межпроцессная защита. С `.31` отмена ожидающего плана через `PlanSession.cancel()` использует тот же guard; во время работы метода она возвращает `session_busy`, не прерывая `apply`. CLI обрабатывает строки последовательно и вызывает этот метод; отмена не откатывает завершённую запись. `missing_params`, `listed` и `no_change` — не планы
с билетом. Вывод может содержать тела правил и диффы; не отправляйте его тем, у кого нет прав.

Интерфейс не определяет, кому принадлежит вызывающий процесс и видел ли человек дифф: переданный
билет сам по себе не удостоверение согласия. Нет авторизации, защиты от конкурентной записи или
гарантии восстановления после сбоя питания. Настройки Kilo, чтение агентом и применение правил
не проверяются. На Windows укажите абсолютный путь текущего дерева вместо примера выше.
