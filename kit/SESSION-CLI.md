# Сессионный интерфейс операций Kit

Интерфейс связывает уже существующую раскладку v2 и `PlanSession` в одном процессе. Он не
устанавливает Kit, не создаёт отсутствующие реестры и не выдаёт прав. Требуется Python 3.10+.
Для ограниченной сессии из закреплённых исходных байтов предусмотрен отдельный опытный
[`snapshot_session.py`](SNAPSHOT-SESSION.md); прямой вызов ниже такой проверки не выполняет.

```text
python3 -B kit/session_cli.py --workspace /absolute/workspace --profile-root profiles/pilot --profile-id Pilot
```

На стандартный ввод по одной строке UTF-8 JSON (не интерактивный естественный диалог):

```json
{"type":"plan","request":"Покажи правила в профиле Pilot."}
```

Каждый ответ — одна JSON-строка на stdout. Для мутации `plan` возвращает `outcome: planned`,
точный дифф и билет. Вызывающий код **показывает дифф владельцу и получает его отдельное
подтверждение**. Затем, в том же процессе, передаёт полный объект плана и подтверждённый билет:

```json
{"type":"apply","plan":{"...":"полный объект ответа plan"},"confirmed_ticket":"билет, подтверждённый владельцем"}
```

Пример выше показывает форму, не готовый применимый план. Для `delete` нужен также явно
`"allow_delete": true`. Команда `{"type":"cancel"}` отзывает ожидающий план. Новый план,
некорректный запрос и завершение процесса также снимают ожидание. Билет одноразовый;
после дрейфа или отказа нужен новый план. `missing_params`, `listed` и `no_change` — не планы
с билетом. Вывод может содержать тела правил и диффы; не отправляйте его тем, у кого нет прав.

Интерфейс не определяет, кому принадлежит вызывающий процесс и видел ли человек дифф: переданный
билет сам по себе не удостоверение согласия. Нет авторизации, защиты от конкурентной записи или
гарантии восстановления после сбоя питания. Настройки Kilo, чтение агентом и применение правил
не проверяются. На Windows укажите абсолютный путь текущего дерева вместо примера выше.
