# Сравнение части данных 0.1.36 и v2: не миграция

Это предварительный сравнитель **явно переданных байтов**. Он не открывает файлы по путям,
не запускает старый Kit, не сканирует проект, не пишет и не устанавливает правила. Пользователь
сам отвечает за разрешение на чтение, безопасное получение и передачу данных. До передачи
реального проекта нужна отдельная процедура; тесты этой команды используют синтетические данные.

## Что передаётся

Python API:

```python
from kit.compare_old import compare
report = compare(
    source={'state': state_bytes, 'checks': checks_bytes, 'base_rules': base_rules_bytes},
    candidate={'registry': new_l2_bytes, 'preserved_state': state_copy_bytes,
               'preserved_checks': checks_copy_bytes, 'preserved_base_rules': base_rules_copy_bytes},
)
```

`state`, `checks`, `base_rules` — данные старого проекта схемы 1 (`state.json`, `checks.json`,
базовый `rules.json`); в `state.base.version` должна быть указана версия `0.1.36`. `registry` —
документ L2 v2 или его контейнер с проверяемым журналом. Три `preserved_*` — переданные
вызывающим копии исходных байтов. Это **не** доказывает, что копии где-то сохранены, доступны
после миграции или защищены от подмены. Каждый вход обязателен, непустой, не более 2 МиБ.

CLI читает из stdin один JSON-объект с теми же картами и `format: 1`; значения — base64
исходных байтов. Для подготовки JSON используйте доверенный вызывающий код, не отправляйте
данные в чат или внешнюю модель. Команда возвращает только диагностический JSON на stdout:

```text
python3 -I -S -B kit/compare_old.py < input.json
```

JSON и временные файлы могут содержать все правила, историю и персональные данные. API не
создаёт `input.json`; кто его использует, отвечает за разрешения и хранение. Отчёт тоже
содержит ID, имена проверяемых полей и хеши, которые могут быть чувствительными.

## Проверяемый объём и исходы

Сравниваются множества ID проектных записей `P-*`, проектная ревизия, вид, заголовок,
состояние, scope, текст, basis, criterion, родитель и пара key/value. `null/null` в старой
паре соответствует отсутствию `key/value` в v2. Три переданные архивные копии сравниваются
с оригиналами **побайтно**, в том числе с историей и полями старого формата. Проверяется
форма целевого L2 и имеющегося журнала; для старой формы — только необходимая выборка полей,
а не полная проверка исходного Kit.

- `core_and_archives_equal` — совпали эти выбранные поля, ревизия и три набора байтов.
- `differences` — обнаружены отличия, пропуски или лишние записи; в отчёте поля и ID,
  но не значения и не тексты.
- `blocked` — проектная запись ссылалась на системный контракт `B-*`, проект выведен из
  эксплуатации (`retired`) или есть следы удаления (`tombstones`). В v2 родитель должен
  быть в том же документе; автоматической перепривязки или копирования системного контракта
  здесь нет. Для `retired` и `tombstones` ещё нет доказанного переноса ограничений в runtime;
  простая копия старых байтов не запрещает повторное использование ID. Остальные отличия
  также перечисляются.
- `error` с кодом процесса `1` — неверный вход, неизвестная версия или недопустимый L2.

Код процесса `0` означает, что сравнение состоялось, **не** что миграция прошла: и
`differences`, и `blocked` тоже возвращают `0`. При любом исходе `migration_ready: false`.
Список `not_checked` обязателен: среди прочего не доказаны здоровье и подлинность источника,
целостность установленной базы, отсутствие pending, отсутствие конфликтов в источнике и
назначении, доступность старых истории и проверок в новом runtime, перенос метаданных записи,
старого счётчика ID и признака вывода проекта
из эксплуатации, поведение scope, сохранение действующих базовых правил, работа целевого
CLI и восстановление. В частности, старый scope сравнивался без учёта регистра, а в v2 он
чувствителен к регистру: совпадение строк ещё не доказывает равное действие.

Даже `core_and_archives_equal` — не `compat --old`, не разрешение на запись и не приёмка
И-131/G5. Для результата без потерь нужны проверка здорового снимка и pin, полная процедура
переноса и извлечения истории/проверок, разрешение межслойных ссылок, защита от pending,
сквозной запуск нового CLI и восстановление после сбоя. Не убирать эти требования из цели.
