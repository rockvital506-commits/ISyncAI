# Локальный guard: ограниченная проверка без модели

Это **экспериментальная разовая команда**, не установленный hook, не GitHub Action и не
закрытие ворот G3. Она ничего не устанавливает и не меняет. Цель — остановиться при
конкретных расхождениях выбранных снимков, а не доказывать, что вся система безопасна.

## Что нужно доверять заранее

1. Самому проверяющему: `guard.py`, импортируемым им модулям `verify_candidate.py` и
   `kit/base/`, Python и окружению. Запускайте их из **отдельной доверенной копии**, не из
   проверяемого изменяемого снимка. Недоверенный guard может выдать любой ответ. Здесь ещё
   нет защищённого распространения, подписи или автоматического установщика доверенной копии.
2. Двум SHA-256, заранее полученным из независимого доверенного источника: хешу точных байтов
   манифеста кандидата и хешу точных байтов `kit/base/registry.json` в проверяемой раскладке.
   Хеш, вычисленный только из того же непроверенного снимка, не устанавливает происхождение.
3. Явному праву проверять выбранный workspace и профиль. Снимок кандидата и workspace —
   разные корни: исходный кандидат сам по себе не содержит рабочего системного реестра.

Для одной ограниченной сессии [`snapshot_session.py`](SNAPSHOT-SESSION.md) закрепляет в памяти
проверенные байты модулей и вызывает guard перед каждой командой. Сам этот guard не проверяет,
какой код другой процесс исполняет из workspace; отдельный загрузчик не устраняет гонок.

Пример с подстановкой собственных путей и заранее проверенных хешей:

```text
python3 -I -S -B /trusted/DomainAgentKit/kit/guard.py --candidate-root /snapshot/DomainAgentKit --workspace /project --profile-root profiles/pilot --manifest-pin <sha256-манифеста> --system-pin <sha256-L0-реестра>
```

`-I -S -B` изолирует импорт от текущего каталога, пользовательского `PYTHONPATH` и site и
не создаёт Python bytecode; зависимости импортируются из дерева рядом с доверенным guard.
Физический проект, права ОС и доверие к интерпретатору это не изолирует.

## Результат и границы

- `pass`, код процесса `0`: снимок кандидата совпал с обязательным pin и своим манифестом;
  выбранный L0 совпал с отдельным обязательным pin; три реестра и имеющаяся история
  прочитались и прошли схему; структурных конфликтов активных `key/value` в перекрывающихся областях не
  найдено. Исходные SHA-256 включены в ответ. Указаны число активных записей без `key/value`
  (`unstructured_active_entries`) и `text_conflicts: not_checked`.
- `violation`, код процесса `1`: отсутствующий/неверный pin, непроверенный кандидат или
  workspace, несовпадение L0, ошибка схемы либо структурный конфликт. Причина — стабильный
  код; содержимое записей и потенциальные победители в ответ не копируются. Ошибки разбора
  аргументов командной строки возвращаются самим Python как ошибка, не `pass`.

Не проверяются смысловые конфликты обычных текстов, авторство/подписи, секреты, право на
мутацию, неизменность L1/L2, установленный `.md`, корректность приложения правил моделью,
проверка Git index/commit или автоматический запуск при commit/PR. Отсутствие формального
конфликта — не утверждение об отсутствии всех конфликтов. Команда не навязывает запрет:
отдельная доверенная система должна запускать её и учитывать код выхода. До этого никакое
принуждение в CI не заявляется.

Проверки файлов выполняются последовательно, без блокировок и изоляции от конкурирующих
процессов. Состояние может измениться во время или после проверки. Это не защита от
вредоносного процесса с теми же правами, подмены интерпретатора, аварии или намеренно
огромных недоверенных входов. Чтение может изменить системный atime. Отчёт и хеши могут
содержать чувствительные метаданные — не публикуйте их без разрешения.
