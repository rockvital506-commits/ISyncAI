# Проверка кандидата в конкретном Git tree

Экспериментальная **разовая** проверка L0-кандидата в Git-объектах без checkout и без запуска
кода из проверяемого tree. Она не устанавливает hook или CI и не проверяет PR/commit/index,
раскладку профиля или работу среды. Для трёх реестров и формальных конфликтов существует
отдельный [guard](GUARD.md); эти две проверки пока не объединены в автоматическое принуждение.

## Требования к доверию

Используйте отдельную доверенную копию `guard_tree.py` **и** её `verify_candidate.py`,
доверенный Python и Git. Проверяемое дерево не должно поставлять исполняемые модули
проверяющему. Необходимо заранее доверять SHA-256 байтов манифеста по независимому каналу:
хеш, вычисленный только из проверяемых объектов, не доказывает происхождение. Также задайте
корень репозитория и **полный OID именно объекта tree** (`sha1` или `sha256` по формату
репозитория). Разрешения на работу с выбранным репозиторием определяет владелец.

```text
python3 -I -S -B /trusted/AgentContractKit/kit/guard_tree.py --repo /path/to/repository --tree <полный-oid-tree> --manifest-pin <доверенный-sha256-манифеста>
```

Пример — схема; угловые скобки нужно заменить значениями. Какому коммиту/PR принадлежит
этот tree, вызывающая сторона устанавливает и проверяет отдельно. В частности, tree, ранее
полученный из index, может уже не совпадать с текущим index. Команда не выполняет
`git write-tree` и ничего не добавляет в index. `-I -S -B` изолирует импорт от текущего
каталога, пользовательского `PYTHONPATH` и site и не создаёт Python bytecode.

## Что считается результатом

`pass` и код `0`: хеш манифеста совпал с переданным pin, состав и SHA-256 включённых файлов
совпали с манифестом, имена в `kit/base/` допустимы и все проверяемые Git-элементы — обычные
blob с режимом `100644`. Ответ содержит `tree_oid`, формат Git, версию и число файлов.
Другие пути репозитория вообще не проверяются. `violation` и код `1`: невалидный ввод,
объект, режим или состав, отсутствие pin, расхождение байтов либо ошибка чтения Git.
Диагностика не выдаёт содержимое объектов. Ошибки разбора аргументов дают ненулевой код.

Команда отдельно читает объекты и не обещает защиты от подмены исполняемого Git, его
библиотек, метаданных репозитория или процесса с теми же правами. Отключаются наследуемые
Git-переменные, пользовательская/системная конфигурация, интерактивные запросы, lazy fetch
на поддерживающем Git и доступные Git-протоколы; конфигурация и хранилище выбранного
репозитория остаются частью доверенной среды Git. Это не песочница для враждебного Git или
репозитория и не гарантия для намеренно огромных объектов. Чтение может изменить atime.

Сверяются только объявленные L0-байты и состав `kit/base/`: не проверяются семантические
конфликты, подписи, L1/L2, установленное правило, другие файлы или состояние после проверки.
Принуждение возникнет только при надёжной интеграции с конкретным действием commit/PR и
доверенным происхождением pin и исполняющего кода; пока CI и G3 остаются `not run`.
